# iPhone release: from this repo to TestFlight

Refs CORE-MOBILE-7 (store releases) and founder item F-3 (Apple account). The pipeline is built and waits for your Apple account. Nothing here needs an iPhone, a Mac or any secret until you want a build on TestFlight.

**What TestFlight is.** Apple's own beta channel. You upload a signed build to App Store Connect, Apple scans it, and it appears in the TestFlight app on your iPhone (and on up to 100 internal testers' phones, no review). The public App Store comes later and adds Apple's review.

## What works today without secrets

| Piece | Where | Proven by |
|---|---|---|
| Unsigned iPhone simulator build (Release, JS embedded) | `ci-mobile.yml` job `ios` | every PR touching `mobile/` |
| App Store pre-flight: 1024 px icons, export-compliance flag, privacy manifest, local-network text | `npm run check:ios`, `ci-mobile.yml` job `test`, jest `scripts/check-ios-release.test.ts` | every PR touching `mobile/` |
| `PrivacyInfo.xcprivacy` is generated and added to the Xcode target | `app.json` `ios.privacyManifests`; checked after `expo prebuild` in both workflows | `ci-mobile` job `ios`, `release-ios` |
| Export compliance (`ITSAppUsesNonExemptEncryption = false`) | `app.json` `ios.config.usesNonExemptEncryption` | `release-ios` |
| Launch screen and a transparency-free App Store icon | generated by `expo prebuild`; `release-ios` fails if missing or if the icon has alpha | `release-ios` |
| Signed archive, IPA, TestFlight upload | `.github/workflows/release-ios.yml` | **not yet run**: needs the secrets below |

`release-ios` without the secrets still runs the free checks, then prints a notice naming the missing secrets and stops green. It never reads a signing secret on a pull request or a feature branch (main or a `mobile-v*` tag only).

## What you must buy and create (once)

1. **Apple Developer Program**, US$99 per year, at developer.apple.com/programs. Enrol as an individual (days) or as an organisation (needs a D-U-N-S number, weeks). The legal name shown on the App Store is the enrolled one, so decide this before enrolling. Apple's current fee and steps are on that page (UNVERIFIED here: checked from memory, confirm at enrolment).
2. **App record**: App Store Connect, My Apps, plus, New App. Platform iOS, name OneMind, bundle id `os.onemind.mobile` (it must match `app.json`; register it first under Certificates, Identifiers & Profiles, Identifiers), SKU anything.
3. **App Store Connect API key**: Users and Access, Integrations, App Store Connect API, generate a key with the **App Manager** role. Download the `.p8` once (Apple shows it only once). Note the Key ID and the Issuer ID at the top of the page.
4. **Apple Distribution certificate**: on a Mac, Keychain Access, Certificate Assistant, Request a Certificate from a Certificate Authority (saved to disk); upload that request at developer.apple.com, Certificates, plus, Apple Distribution; download and open the `.cer`; in Keychain Access export the certificate with its private key as `.p12` and choose a password. The `.p12` is the only copy of the private key: keep a backup outside the repo.
5. Team ID: developer.apple.com, Membership details, Team ID (ten characters).

## Secrets to add

GitHub, repository Settings, Secrets and variables, Actions, New repository secret. Names are exact.

| Secret | Value |
|---|---|
| `APPLE_TEAM_ID` | the ten-character Team ID |
| `ASC_KEY_ID` | the API key's Key ID |
| `ASC_ISSUER_ID` | the Issuer ID (a UUID) |
| `ASC_KEY_P8_BASE64` | `base64 -i AuthKey_XXXX.p8` output, one line |
| `IOS_DIST_CERT_P12_BASE64` | `base64 -i dist.p12` output, one line |
| `IOS_DIST_CERT_PASSWORD` | the `.p12` password |

Provisioning profiles need no secret: `xcodebuild -allowProvisioningUpdates` with the API key creates and fetches the App Store profile for `os.onemind.mobile`. Never commit any of these files.

## First TestFlight steps

1. Add the six secrets. Run Actions, release-ios, Run workflow, branch `main`. (A tag `mobile-vX` also runs it; keep the tag in step with `app.json` `version`.)
2. Watch the job: pre-flight, prebuild checks, archive, export, upload. Each run sets the build number to the run number, so every upload is accepted.
3. In App Store Connect, TestFlight, wait for "Processing" to finish (minutes to an hour). Answer the compliance prompt if it still appears (see below).
4. Internal Testing, plus, create a group, add yourself (an Apple ID on your team), enable the build. Install the TestFlight app on the iPhone and accept the invite.
5. The app needs a hub on the same network (README, "Connect"); iOS asks for Local Network access on first use.

## Decisions and answers Apple asks for

- **Export compliance.** `ITSAppUsesNonExemptEncryption = false` says the app uses only encryption that Apple's OS provides or that is exempt (HTTPS, signatures for authentication). OneMind's own crypto (`@noble/*`) is used for signing and key derivation toward the user's own hub; confirm that reading yourself before the first App Store release, because it is a legal declaration and yours to make.
- **Privacy label ("nutrition label").** The app sends photos, device info and approvals only to the user's own OneMind box, never to the developer or a third party, so "Data Not Collected" applies, and the manifest lists no collected types and no tracking. Re-check if a push relay (#208) or analytics is ever added.
- **Required-reason APIs** declared in the manifest (file timestamps, UserDefaults, boot time, disk space) are the set Expo's own modules use; Apple's upload check names any missing one by email.
- **Passkeys** need the relying-party name linked to the app (README, "Passkeys": decision pending), which adds an Associated Domains entitlement. Not in this lane yet.
- **Push on iPhone** stays on #208 (founder decision needed); the lane builds no relay and `aps-environment` is not set, so no push entitlement is requested.

## Not proven yet (UNVERIFIED)

The signed path (keychain import, automatic signing with the imported distribution certificate, `altool` upload) follows Apple's documented `xcodebuild` and `altool` options but has never run, because no Apple account exists yet. Expect one or two fix-up runs after the first real attempt. Apple has been moving uploads from `altool` to the Transporter tools; if `altool` is refused, swap the last step for `xcrun iTMSTransporter` with the same API key.

App Store review (the public listing) needs more than this lane: screenshots at Apple's required sizes (the current ones predate v1, README "Screenshots"), a privacy policy URL, support URL, and age rating answers.
