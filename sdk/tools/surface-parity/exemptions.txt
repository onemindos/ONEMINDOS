# Surface parity exemptions (sdk/tools/surface-parity; BUILDER-BRIEFING item 6; #1232).
#
# The rule: every API operation has a dashboard caller, every operation that changes something
# (POST, PUT, PATCH, DELETE) has an `onemind` command, and every operation in the phone's scope
# below has a phone caller. Anything that does not is listed here, under a group with a reason and
# an owner issue. This list only shrinks:
#   - a new operation never goes here to get green: build its screen and command in the same PR,
#     or argue a group in review ("Not done" in the PR body);
#   - when a caller lands, the test reports the line as stale: delete it in that PR;
#   - an operation that leaves the spec must leave this file too.
#
# Lines:
#   mobile-scope <tag> [/path/prefix ...]   the phone checks this OpenAPI tag (narrowed to the prefixes)
#   group <name> issue=#<n> <reason>        a reason and the issue that owns closing it
#   <dashboard|cli|mobile> <operationId> <group>
#   indirect <dashboard|cli|mobile> <operationId> <reason>
#       a person CAN do this on that surface, but the scanner sees only the path (kept in a table or
#       a variable and sent by a helper), not the HTTP method. A path-only literal never counts by
#       itself (it would stand for every method on the path, so a new DELETE next to a known GET
#       would pass unseen); it counts for the operation only with this line. The reason says where the
#       method is sent. The line fails when a method-aware caller appears (delete it) or when no file
#       on that surface names the path any more (the caller is gone: list the gap under a group).
#
# Run `python3 -I sdk/tools/surface-parity --report` for the whole matrix.
