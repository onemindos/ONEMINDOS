# Breaking changes

 - Dropped /usr/libexec from the persistent state paths in 00_rootfs.yaml (fixes https://github.com/kairos-io/kairos/issues/4304). /usr/libexec is image content, not runtime state, and persisting it broke Kubernetes cluster builds and broke rollback across OS versions. The cloud config should add any required folders as ephemeral (e.g. /usr/libexec/kubernetes) rather than persisting them. (An example is avalable at https://github.com/kairos-io/kairos/blob/v4.4.0/examples/cloud-configs/ephemeral-usr-libexec.yaml)
 - immucore now fails the boot when the persistent state binds cannot be mounted (fixes https://github.com/kairos-io/kairos/issues/4782). Previously, if any disk named in rd.cos.mount=, rd.immucore.mount= or VOLUMES was missing or failed to mount, immucore skipped every bind in PERSISTENT_STATE_PATHS (/home, /root, /opt, /var/lib/..., etc.) and booted anyway. The same happened when an overlay path failed or the layout config could not be read. The node came up on the pristine image /etc with no persistence: SSH host keys were regenerated on every boot, logs went to the ephemeral overlay and k3s/k0s lost their state dir. The only trace was an empty warning line in the logs. Now the boot stops with an `IMMUCORE BOOT FAILED` banner that names the step and the mount that broke, along with its error, and the failure is also written under /run/immucore. On a normal GRUB boot dracut drops to its emergency shell, and on UKI/Trusted Boot immucore drops to an emergency shell with the error. COS_OEM failures in the custom mounts and overlay paths that don't exist in the image are still tolerated. Under UKI only a bind that itself failed stops the boot, not an upstream custom mount. Before upgrading, check that every disk named in rd.cos.mount / rd.immucore.mount / VOLUMES actually exists on the node: a node that was silently booting without persistence will now stop at boot instead.

# Important changes

 - CIS Level 1 hardening is on by default in kairos-init images (#4650, #4907, #5035, #5096, #5277). Node behaviour changes in several ways:
   - Accounts lock for 15 minutes after 5 failed logins, and this includes root.
   - New passwords must be at least 14 characters, and they expire after 365 days.
   - su is limited to the wheel group, and the default umask is 027.
   -  auditd is installed with immutable rules (-e 2), so changing them needs a reboot. journald now stores logs persistently.
   -  New sysctls go in /etc/sysctl.d/99-kairos-cis.conf, including net.ipv6.conf.all.accept_ra = 0. Edge sites that use IPv6 router advertisements should test this.
   -  sshd gets a login banner and PermitUserEnvironment no.
   -  To opt out at build time, use kairos-init `--skip-step cisHardening`

- /tmp is now mounted noexec and /dev/shm is remounted noexec. immucore does this, so --skip-step cisHardening does not turn it off. Any script, installer or agent that runs a binary from /tmp will fail.
