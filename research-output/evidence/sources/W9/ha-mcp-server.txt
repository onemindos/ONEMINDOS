 Model Context Protocol

 The Model Context Protocol (MCP) integration lets you connect an AI agent, such as ChatGPT or Claude, to Home Assistant. The AI agent can then control your devices and see the current state of your home.

With this integration, Home Assistant is the MCP server. Home Assistant groups the tools it offers to AI agents into sets of tools. The AI agent can use the sets of tools that you allow, which by default is all of them. One of these is Device control, which gives the AI agent the same tools as your voice assistant (Assist). With Device control, it can only control or see the entities that you have exposed on the exposed entities page. Another one is Home Assistant, which can read all entities, logs, and history, and perform any action. To choose which tools the AI agent can use, refer to Configuration options.

 Tip

Home Assistant has two MCP integrations, and they work in opposite directions:

Model Context Protocol (this page): Another AI app, such as Claude or ChatGPT, controls Home Assistant.

Model Context Protocol Client: Your Home Assistant conversation agent uses tools from another service.

If you want your Home Assistant conversation agent to use tools from another service, such as web search, you need the Model Context Protocol Client integration.

Prerequisites 

Your MCP server URL. To get it:

Go to Settings > System > AI.

If the Model Context Protocol card shows an Enable button, select it.

Next to the URL you want to use, select the copy icon . We recommend Main URL. By default, it exposes all tools, and you can change this in the configuration options. Under Individual URLs, each set of tools also has its own URL.

An AI agent that supports MCP servers.

If the AI agent runs in the cloud, for example when you use it through a website, your Home Assistant instance must be accessible from the internet. Use Home Assistant Cloud or another method of remote access.

For detailed configuration instructions, refer to the Client configuration section.

Configuration 

To add the Model Context Protocol service to your Home Assistant instance, use this My button:

 Manual configuration steps

If the above My button doesn’t work, you can also perform the following steps
manually:

Browse to your Home Assistant instance.

Go to Settings > Devices & services.

In the bottom right corner, select the
 Add Integration button.

From the list, select Model Context Protocol.

Follow the instructions on screen to complete the setup.

When you set up the integration, the main URL exposes all tools and requires an administrator account. To change this, go to Settings > Devices & services, select Model Context Protocol, and then select Configure.

Configuration options 

The integration provides the following configuration options. They only apply to the main URL (/api/mcp), shown as Main URL in Settings > System > AI.

Each set of tools also has its own URL, listed under Individual URLs. For example, /api/mcp/assist only exposes Device control. These URLs ignore the options below. They are never read-only, and all of them except the Device control URL require an administrator account.

Expose all AI tools

If the main URL exposes every set of tools, including sets of tools that integrations add later. This option is turned on by default. If you set up the integration before this option existed, it stays turned off so that your clients keep the tools you selected. Turn it off to select individual sets of tools.

AI tools

The sets of tools that the main URL exposes when Expose all AI tools is turned off. Device control only accesses the entities you expose to voice assistants. Home Assistant accesses everything and requires an administrator account.

Require an administrator account

If only administrator accounts can use the main URL. This option is turned on by default. If you set up the integration before this option existed, it stays turned off so that your clients keep working. When the main URL exposes Home Assistant, for example with Expose all AI tools, an administrator account is always required.

Read-only

If the main URL only exposes tools that are marked as not changing anything, such as getting the current state of your home. This option is turned off by default.

Client configuration 

Home Assistant implements the standard Model Context Protocol, including OAuth 2.0 with PKCE. It supports OAuth Client ID Metadata Documents, so AI agents set up the client ID and callback URL automatically.

Example: Claude 

Before you start, copy your MCP server URL as described in the prerequisites.

 Note

Claude connects to your MCP server from the cloud, also when you use Claude Desktop. Your Home Assistant instance must be accessible from the internet.

Open the form to add a connector:

On claude.ai, go to the Claude connectors page. In the top-right corner, select Add > Add custom connector.

In Claude Desktop, go to Settings > Connectors and select Add > Add custom connector.

Enter the following details:

Name: Home Assistant

MCP Server URL: Paste your MCP server URL.

Select Add.

Claude verifies the MCP server and shows a dialog. Enter the following details:

Authentication: Select Sign in now.

OAuth client: Select Use Claude’s published identity.

Select Add.

On the page for your new connector, select Connect.

Log in to your Home Assistant instance.

You can now enable tools from Home Assistant when chatting with Claude, allowing you to control Home Assistant in a similar way to how you control it through the Voice Assistant. Claude will ask you for permission before calling any tools.

Example: ChatGPT 

Before you start, copy your MCP server URL as described in the prerequisites.

 Note

If you use ChatGPT on chatgpt.com, your Home Assistant instance must be accessible from the internet.

Open the form to add an MCP server:

On chatgpt.com, go to the ChatGPT plugins page. In the top-right corner, select Add > Add custom MCP server.

In ChatGPT Desktop, go to Settings > Plugins and select Add > Add MCP server.

Enter the following details:

Name: Home Assistant

Connection: Paste your MCP server URL.

Authentication: Select OAuth.

Select I understand and want to continue.

Select Create as plugin.

ChatGPT offers to Connect Home Assistant. Select Continue to Home Assistant.

Log in to your Home Assistant instance.

Example: Claude Code 

Claude Code connects to MCP servers over HTTPS only. Use the MCP server URL of your remotely accessible Home Assistant instance, as described in the prerequisites.

Install Claude Code and log in.

In your terminal, run the following command. Replace <your_mcp_server_url> with your MCP server URL.

claude mcp add --transport http home-assistant <your_mcp_server_url>

Run the following command:

claude mcp login home-assistant

In your web browser, log in to your Home Assistant instance.

You can now enable tools from Home Assistant when chatting with Claude, allowing you to control Home Assistant in a similar way to how you control it through the Voice Assistant. Claude will ask you for permission before calling any tools.

Example: Codex 

Install Codex and sign in.

In your terminal, run the following command. Replace <your_mcp_server_url> with your MCP server URL, for example http://homeassistant.local:8123/api/mcp.

codex mcp add homeassistant --url <your_mcp_server_url>

Codex opens your Home Assistant instance in your web browser. Log in to your Home Assistant instance.

Example: OpenCode 

Install OpenCode.

In your terminal, run the following command. Replace <your_mcp_server_url> with your MCP server URL.

opencode mcp add home-assistant --url <your_mcp_server_url>

Run the following command:

opencode mcp auth home-assistant

In your web browser, log in to your Home Assistant instance.

Supported functionality 

Tools 

MCP Tools enable LLMs to
perform actions through Home Assistant. In Home Assistant, a set of tools is
called an LLM API. The tools used by the configured LLM API are exposed.

Prompts 

The MCP Prompts provided
inform LLMs how to call the tools. Home Assistant provides one default prompt for
the configured LLM API, which contains the instructions of that LLM API.

Resources 

When the configured LLM API includes the GetLiveContext tool, Home Assistant
also exposes a read-only MCP Resource
named homeassistant://assist/context-snapshot.

This resource returns a plain-text snapshot that matches the existing
GetLiveContext tool output. It is intended for inspection, debugging, and
explanation workflows where a static snapshot is useful. If the configured LLM
API does not expose GetLiveContext, this resource is not available.

Known limitations 

The Home Assistant Model Context Protocol integration currently only supports a
subset of MCP features:

Prompts: Supported

Tools: Supported

Resources: Supported (Device control only)

Sampling: Not supported

Notifications: Not supported

Troubleshooting 

Repeated OAuth failures 

Symptom: Unable to access Home Assistant after several failed login attempts 

If authentication keeps failing during the OAuth setup flow, the most likely cause is that one or more OAuth details are incorrect, such as the client ID or the Home Assistant URL.

Resolution 

Review the OAuth configuration in your client and verify the details:

Make sure the Client ID is the base URL of the LLM client application (for example, https://claude.ai for Claude or https://chatgpt.com for ChatGPT), and never your Home Assistant instance URL. IndieAuth validates that the redirect URI shares the same scheme and domain with the client ID; setting the client ID to your Home Assistant instance causes the authorization flow to fail.

Home Assistant does not use a client secret. If the field is required by the client application, enter any text; if it is optional, leave it blank.

Make sure the URL used to access Home Assistant matches the configured Internal URL or External URL in Settings > System > Network.

If you have explicitly enabled IP bans in Home Assistant and repeated failed sign-in attempts caused a ban, check the ip_bans.yaml file in your Home Assistant configuration directory. If your computer’s IP address or the client’s IP address is listed there, remove it, restart Home Assistant, and then try authenticating again.

Symptom: OAuth discovery fails or authorization server metadata is rejected 

When connecting an external client (such as ChatGPT or Claude) through a tunnel, reverse proxy, or custom domain, the client fails to complete OAuth discovery or rejects the metadata with an error regarding the issuer or registration endpoint.

Description 

This can occur for two reasons:

Hostname or proxy mismatch: Home Assistant checks incoming requests against its configured internal and external URLs. If the hostname used by the remote LLM client does not match the configured URL, or if reverse-proxy headers (X-Forwarded-Host, X-Forwarded-Proto) are missing or mismatched, Home Assistant cannot resolve the issuer in /.well-known/oauth-authorization-server and returns relative paths. Conforming OAuth clients reject this metadata because RFC 8414 requires the issuer to match the URL used to discover it.

Unsupported Dynamic Client Registration (RFC 7591): Home Assistant uses the draft-ietf-oauth-client-id-metadata-document standard (client_id_metadata_document_supported: true) rather than RFC 7591 Dynamic Client Registration. LLM clients that strictly require RFC 7591 Dynamic Client Registration cannot register automatically.

Resolution 

Go to Settings > System > Network and make sure that the External URL (or Internal URL) matches the exact hostname and scheme used by the remote LLM client to reach Home Assistant.

If using a reverse proxy or tunnel (such as Cloudflare Tunnel), make sure Home Assistant is configured to trust forwarded headers from the proxy. See Reverse proxies in the HTTP integration documentation for details on configuring Trust X-Forwarded-For and Trusted proxies.

If the LLM client supports manual OAuth configuration (such as ChatGPT’s user-defined OAuth client), enter the authorization and token endpoints manually rather than relying on automatic discovery.

Using Home Assistant Cloud (https://<your-id>.ui.nabu.casa) avoids reverse-proxy and tunnel configuration pitfalls because it automatically handles canonical hostnames and SSL termination.

Removing the integration 

This integration can be removed by following these steps:

To remove an integration instance from Home Assistant 

Go to Settings > Devices & services and select the integration card.

Next to the entry you want to remove, select the three dots menu. Then, select Delete.

Depending on the integration, the entries are listed under one of the following headings:

Devices

Hubs

Services

Integration entries

To confirm, select Delete.

Home Assistant also deletes the devices and entities of the entry.

If Home Assistant asks you to restart, restart Home Assistant.

If Home Assistant asks whether to also delete the application credentials, select Remove or Keep.

If you keep them, Home Assistant uses them automatically when you add the integration again.

To delete them later, refer to Deleting application credentials.
