Stable means included in an official HAMi release. Release status in this table is checked against v2.11.0. Experimental means the integration is still in development or validation and has not been officially released.
Teco integration has not been merged into the Next baseline above. Device models and capabilities remain to be validated. Track progress in HAMi #3369 and documentation PR #979.
Capability columns:
Memory control: The memory quota or partition size that a container can request. Templates and fixed partition sizes round memory allocations up to the corresponding size.
Compute control: Devices control compute resources through time slices, core allocation, hardware partitions, or QoS policies. See the linked references in the table for limitations.
Multi-card partitioning: A single container can allocate resources across multiple physical devices while using only part of the resources on some of those devices. Allocating only whole devices does not count as multi-card partitioning. See the linked references for allocation granularity and limitations. N/A means the mode allocates whole devices only.
Component integration guides​
For NVIDIA sharing, Volcano vGPU and KAI Scheduler retain their own scheduling capabilities and use HAMi-core for runtime isolation; the KAI Scheduler integration provides memory isolation. HAMi-DRA works with the Kubernetes scheduler through DRA drivers; its NVIDIA sharing path uses HAMi-core to enforce memory and compute limits at runtime.
