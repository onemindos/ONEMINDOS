title: RPi 5 Fatal Firmware Error (Code 45) with Multiple USB MSDs

### Describe the bug

The Raspberry Pi 5 fails to complete the boot process via USB Mass Storage Device (MSD) when a secondary USB storage device (Pendrive) is connected. The system halts with a USB MSD stopped. Timeout: 25 seconds and a Fatal firmware error (Code 45). This issue began immediately after an apt upgrade that included the latest EEPROM version (2025/11/05). The failure points to a critical regression in the USB enumeration code when multiple MSDs are present.

The system boots successfully only when the secondary Pendrive is physically disconnected during power-on.

<img width="405" height="342" alt="Image" src="https://github.com/user-attachments/assets/47376abb-41e2-4567-a7b0-092ee895011e" />

### Steps to reproduce the behaviour

Set the RPi 5 EEPROM to boot from USB MSD.

Connect the Primary USB SSD (OS drive, MBR partition table) to a USB 3.0 port.

Connect the Secondary USB Pendrive (Data drive, currently GPT partition table) to the other USB 3.0 port.

Power on the Raspberry Pi 5.

The system fails with a 25-second timeout and the Code 45 Fatal Firmware Error.

### Device (s)

Raspberry Pi 5

### Bootloader configuration.

The system was fully restored, and the configuration was applied with maximum specificity to force boot on the SSD, but the failure persists.

I can confirm that setting **PARTITION_WALK=0** in the bootloader configuration **resolves the issue.**

I performed the following tests:

1.  **Test 1 (Success):** Set `PARTITION_WALK=0` in `bootconf.txt` and applied the changes. The Raspberry Pi 5 **boots successfully** with both the SSD (Primary OS) and the Pendrive (Secondary Data, GPT) connected via USB.
2.  **Test 2 (Failure):** Set `PARTITION_WALK=1` (or commented it out). This immediately reproduces the failure, resulting in the `BOOT ERROR: code 45 - 'Fatal firmware error'`.

Thank you for the quick and accurate diagnosis!
