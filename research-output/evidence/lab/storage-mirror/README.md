# Lab LAB-storage-mirror: btrfs raid1 on LUKS2, pull a disk, re-add, resync

**Status:** COMPLETE, all phases PASS (2026-11-12). **Serves:** STOR-3 (inventory and health), the plan half of STOR-4, and the assumptions behind STOR-2's degraded-boot policy (`docs/umbrel2/storage.md` §4.4, §4.5). **Code:** `internal/storage`, `cmd/onemind/storage.go`.

> **In plain words.** A mirror (RAID 1) keeps two copies of every file on two different disks, so one disk can die without losing anything. This lab builds such a mirror the way OneMind will, with **btrfs** (a Linux filesystem that keeps a checksum for every block, so it knows which copy is right) on top of **LUKS2** (disk encryption). Then it pulls one disk out, keeps using the box, plugs the disk back in and checks that `onemind storage` reports each state correctly and that the generated repair plan brings everything back with no file damaged. Every disk-changing command was generated by `onemind storage plan` and run exactly as printed. In the product, an owner approves the plan first.

## Findings that change the design or the code

1. **A returned disk is stale even when btrfs shows nothing wrong (phase 13).** While mounted degraded, btrfs keeps writing into *existing* raid1 chunks (only the present copy is updated) and allocates `single` chunks only when it needs new space. After the member returns, `btrfs filesystem df`, `show` and `device stats` look perfectly healthy, but the returned disk holds old copies: the scrub found 16 384 checksum mismatches on it (and 260 334 in phase 12). A read that happened to hit the stale copy would be detected by the checksum and served from the good copy, but until the scrub runs the set has **one good copy** of that data. **Consequence:** "protected" cannot be derived from btrfs alone. Implemented: a persistent marker `<data>/onemind/storage/needs-scrub` makes status report DEGRADED until the repair plan's scrub runs, and the plan removes it last. **STOR-2 must write this marker** whenever the initrd mounts degraded (storage.md §4.4 step 3), and step 5 there should read "scrub, then soft-convert balance, then clear the marker".
2. **lsblk lags after `btrfs device add`.** udev does not re-probe the new mapper device, so lsblk showed the new member without a filesystem (`has-data`). Inventory now also matches members by the device paths btrfs reports.
3. **Order matters: scrub first, then the soft-convert balance.** The balance relocated only the 2 single chunks; the stale raid1 copies were fixed only by the scrub. A balance alone would have left them.
4. **cryptsetup warns on a 2 GiB machine** ("keyslot operation could fail as it requires more than available memory"): LUKS2's default argon2id memory cost is sized for bigger machines. Unlock worked here; STOR-1 should pin the PBKDF memory cost for the smallest supported board (Raspberry Pi 5 with 4 GiB, STOR-10) and test unlock there.
5. **Mount option `discard=async` on dm-crypt (UNVERIFIED).** dm-crypt passes discards down only when the mapping is opened with `--allow-discards` (cryptsetup(8)); the plan does not set it, and virtio gave no error either way, so whether discards reached the disk was not checked. STOR-1 should decide explicitly: discards on an encrypted disk reveal which blocks are free.

## Reproduce

```
limactl disk create omst-a --size 6GiB --format raw
limactl disk create omst-b --size 6GiB --format raw
# VM config: base: template:debian-13, additionalDisks: [{name: omst-a, format: false}, {name: omst-b, format: false}]
# inside: apt-get install btrfs-progs smartmontools cryptsetup gdisk nvme-cli jq; install the onemind binary
sudo bash scripts/1-build.sh
# stop VM; set additionalDisks to omst-a only; start
sudo bash scripts/2-degraded.sh
# stop; both disks; start
sudo bash scripts/3-readd.sh
# stop; omst-a only; start
sudo bash scripts/4a-stale-degraded.sh
# stop; both disks; start
sudo bash scripts/4b-stale-readd.sh
```

Raw tool output from phases 2–4 is kept as test fixtures in `internal/storage/testdata/` and replayed by `go test ./internal/storage`.
