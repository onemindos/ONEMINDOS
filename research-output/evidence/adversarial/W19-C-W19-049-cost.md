| Lens | Cost and business |

## 1. Re-check of the cited sources
- Rugix lab (C-LAB-debian-rugix-012): the root overlay is discarded except declared persist paths. umbrelOS #2124 (C-TD-umbrelos-053): SSH changes reset on reboot, and users called it an unannounced breaking change. Both support reserving a sanctioned host-extension path *before* users need one. The umbrel case is itself a business cost: support load and user anger when the path was missing.
- Items 1 and 2 are a config line and two directories, close to zero cost. Item 3 (CONFIG_MODULE_SIG) is a kernel build option that costs nothing until enforced.

## 2. Strongest counter-argument
1. **Items 3 and 4 are not reservations. They are operations.** A module-signing key and a verity signing chain need key custody (an HSM or offline root), rotation, revocation and a signing service in CI from release 1. That is the same recurring cost as E9. The conclusion calls them "cheap now", but they are only cheap if signing is folded into the existing RAUC bundle-signing chain with one key hierarchy. That condition should be stated.
2. **"Merged before k3s" combined with verity signing turns one bad file into an outage of every host plugin.** systemd #32762 (open since 2024-05-11): if one image fails to mount (for example a signature failure, ENODEV from crypt_activate_by_signed_key), "no extension is merged" [C-REF-W19-cost-005]. If driver packs or the profile confext gate k3s workloads, a single corrupt download in /var/lib/extensions can take a box's whole plugin layer down at boot. That is a field-support cost, and it is missing from the flip list.
3. **Signing stacks get retired.** Docker Content Trust and Notary v1 shut down on 2026-12-08 [C-REF-W19-cost-002]. If item 4 is built on a bespoke or niche signing format, OneMind carries a migration later. Use the format systemd verifies natively (verity with a PKCS#7 signature on the image) rooted in the same CA as RAUC.

## 4. What would flip it
Keep the three flip conditions the author lists and **add** two:
- **(d)** On systemd 257.13 with verity signing on, one invalid image blocks all merges, and no graceful mode is available in Debian 13. The decision then needs a OneMind-side quarantine (validate before placing in /var/lib/extensions) before item 4 can ship.
- **(e)** A costed key-management plan shows that a separate module-signing and verity key hierarchy cannot share the RAUC root. Items 3 and 4 then become a recurring cost that release 1 cannot carry.
