# W2 — Refuter report: P0-1 (S1 base OS and image family), technical lens

- **Claim under test (P0-1):** On the frozen scorecard (20/20/15/15/10/10/10), "Ubuntu 26.04 LTS + OneMind's own A/B image + JetPack (Ubuntu) on Jetson" scores 62.0; RHEL-family bootc 56.0, Debian 13 + Rugix 56.0, Yocto+RAUC 51.0, Fedora IoT 48.0, Buildroot+RAUC 46.0, Ubuntu Core 46.0. The winner is the same in all 14 ±5 weight runs (minimum margin 3.9). Main supports: the GPU Operator K3s column lists only Ubuntu, and ROS 2 Lyrical is Tier 1 only on Ubuntu 26.04 (amd64 and arm64).
- **Refuter lens:** technical. I was given only the claim and its sources (RESEARCH-MISSION.md §2 rule 7). I did not read the author's scoring cells.
- **Date:** 2026-11-10
- **Requirement IDs touched:** RS-4, F-2, F-3, F-12, N-2, M-6, M-7, R-1, R-3, H-1

## Verdict: **weakened**

The ranking may well hold, because no other candidate fixes the problems below. But **both main supports describe the x86 and Pi 5 half of the stack, not the Jetson half**, and the claim names Jetson as part of the stack. The cited GPU Operator page says Jetson is not supported at all. On Jetson the stack ships **Ubuntu 24.04** (JetPack 7.2 / L4T 39.2), not 26.04, and Lyrical rates 24.04 **Tier 3**. So "Ubuntu 26.04" is really a split across two Ubuntu releases with two kernel lines. The "own A/B image" does not exist yet. The 6.0-point lead equals **1.5 anchor steps on one 20-weight criterion**. Over-scoring C2 by one anchor turns it into a tie (<3.0). The ±5 weight sweep does not test that risk at all.

## New sources (found by searching for failure, regressions, lifecycle lag)

- **N1. NVIDIA JetPack 7.2 archive:** https://developer.nvidia.com/embedded/jetpack/downloads/archive-7.2 (opened). Jetson Linux 39.2, dated 6/02/2026, with "L4T Ubuntu 24.04" and "Canonical Ubuntu 24.04 for Jetson" as distros, kernel 6.8, for Thor and the Orin family. **No Ubuntu 26.04.** The Canonical Ubuntu for Jetson docs (https://canonical-ubuntu-for-jetson.readthedocs-hosted.com/latest/get-started/, opened) list 22.04 Server, 24.04 Server (Thor) and Core 22. **No 26.04.** The Jetson flavor therefore runs on an Ubuntu release that is two years behind and on a non-LTS 6.8 kernel. Lyrical rates that release Tier 3, and its Lyrical support ends early, in June 2029.
- **N2. Launchpad bug #2170238 (linux-raspi):** https://bugs.launchpad.net/ubuntu/+source/linux-raspi/+bug/2170238 (opened). Filed 2026-10-08, status New, importance Medium. The Ubuntu 26.04 (7.0) kernel stalls at boot on Pi 5s with an EEPROM older than 2025-02-11. Canonical's linux-raspi left out the upstream RPi compatibility commit. Some boards "fail to boot with any EEPROM from 2024-09-23 onward" and are stuck on an older release. For an A/B appliance shipped on customer hardware, the image has to own EEPROM updates, so this is OneMind's problem to solve.
- **N3. Launchpad bug #2127970 (rust-coreutils), duplicate #2129660:** https://bugs.launchpad.net/ubuntu/+source/rust-coreutils/+bug/2127970 (opened). In 25.10, `date -r` silently returned the current time. As a result **unattended-upgrades never ran**, and backup scripts skipped their runs. Importance was raised to Critical. The bug also affected Resolute (26.04) during development, and the fix landed 2025-10-24. This shows that 26.04's move to Rust coreutils is a fresh source of regressions, and that apt-driven security updating on Ubuntu can fail silently. It counts against any score that credits Ubuntu's in-place update path. The A/B image, if built, avoids it.
- **N4. NVIDIA GPU Operator 24.9.1 release notes:** https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/24.9.1/release-notes.html (opened). Known limitation: "On Rancher RKE2 and K3s, NVIDIA Container Toolkit v1.17.0 fails to start". Fixed issue #1109: "would fail to start on Rancher RKE2, K3s, and Canonical MicroK8s." A matrix tick for K3s has not prevented releases that break on K3s. Its value as evidence for C2 or C7 is moderate.
- **N5. Ubuntu "Call for testing: A/B boot on Raspberry Pi":** https://discourse.ubuntu.com/t/call-for-testing-a-b-boot-on-raspberry-pi/64173 (opened). Posted 2025-07-09. Canonical's own `piboot-try` covers the **boot partition only**, not the rootfs. It slows boots by about 1.5–1.7x, and it moves `cmdline.txt`. One test corrupted the boot partition on a flaky SD card. Canonical, which has a large team, ships boot-asset A/B for the Pi only, with no rootfs A/B. "OneMind's own A/B image" would have to build that layer and coexist with `piboot-try`.

## Strongest counter-argument

1. **The stack splits into two releases, and the evidence only covers one of them.** The claim scores the stack as "Ubuntu 26.04". On Jetson, the device that F-2 and F-3 care most about, OneMind actually ships L4T Ubuntu 24.04 with kernel 6.8 (N1). On that flavor the GPU Operator is "not supported" (L244), and ROS 2 Lyrical is Tier 3 with early EOL in 2029. Both "main supports" therefore apply to x86 and Pi 5, where the GPU Operator is irrelevant on the Pi and needed only on x86. Two Ubuntu releases, two kernel lines (linux-raspi 7.0 and the L4T 6.8 BSP) and NVIDIA's own L4T A/B (`nvbootctrl`) make up exactly the "cost of running two flavors" that the frozen scorecard says must count against a candidate under C5. Debian 13 + Rugix and RHEL bootc pay the same Jetson flavor cost, so this does not reverse the ranking. It does remove the Jetson-specific part of Ubuntu's C2 lead.
2. **The A/B framework is unproven, and the rule "unproven cell gets 0" should bite.** "OneMind's own A/B image" has no code, no lab result and no production user. The C3 anchors ≥3 need automatic rollback, health gating and documented power-loss safety. C4 needs shipping products. Debian + Rugix and RHEL bootc are scored with an existing, documented and shipped update framework. If the Ubuntu candidate's C3 or C4 credit comes from Ubuntu itself (Canonical's install base) rather than from the update framework the stack actually uses, the comparison is asymmetric. N5 shows that even Canonical stops at boot-asset A/B on the Pi.
3. **The GPU Operator fact settles S3 before S1 is decided.** RHEL 10 is validated for upstream K8s and RKE2 in the same table. Restate the fact as "only Ubuntu is validated for K3s; RHEL 10 is validated for RKE2/K8s". The bootc candidate's C2 gap then becomes "needs RKE2 instead of k3s", which is a cost for S3, not a fact about the hardware. N4 also shows that the K3s tick has not stopped toolkit breakages on K3s.
4. **The lead is fragile to the scores, and the robustness test only shakes the weights.** Each anchor step is worth 4.0 points on C1/C2, 3.0 on C3/C4 and 2.0 on C5–C7. A 6.0 lead is therefore one C2 step plus one C5 step, or two C3/C4 steps. A single change to an Ubuntu cell, C2 from 4 to 3 (because "one update framework across all three board families" in the C2-4 anchor is not met: Jetson uses L4T A/B, x86 and Pi use an A/B that does not exist yet), brings the lead to 2.0, **a tie under §3**. The 14 ±5 weight runs (minimum 3.9) are not evidence of robustness against anchor misjudgement, which is the larger uncertainty here.
5. **There are lifecycle and regression facts the claim omits.** 26.04 ESM ends in May 2036, not by 2036-12-31 (G3 needs a 28.04 rebase or an unpriced Legacy add-on). The Pi 5 boot regression is open (N2), and 26.04 ships Rust coreutils, which silently broke unattended-upgrades in the cycle before it (N3). None of these is disqualifying, but each sits in a cell that the claim presents as a clear Ubuntu advantage.

## Required corrections to the decision text

- Rename the candidate to what is actually shipped: "Ubuntu 26.04 (x86, Pi 5) + L4T Ubuntu 24.04 / JetPack 7.2 (Jetson) + OneMind A/B (to be built)". Score C5 with the flavor-split cost.
- Restate support 1: "GPU Operator validates K3s only on Ubuntu; it validates RHEL 10 on K8s/RKE2; it does not support Jetson (L244)."
- Restate support 2: "Lyrical Tier 1 on Ubuntu 26.04 amd64/arm64 and Windows 11 amd64; RHEL 10 amd64 Tier 2; Ubuntu 24.04 (the Jetson base) Tier 3, early EOL 2029-06-01."
- Show the per-cell scores together with a **±1-anchor sensitivity run** (each top-two cell moved by one step), not only the weight sweep.
- Record G3 as CONDITIONAL: 26.04 ESM ends 2036-05. Name the 28.04 rebase plan or a bounded Legacy add-on cost.

## What evidence would flip the decision

- **To a tie or a loss against RHEL bootc:** (a) the author's C2 or C3/C4 cell for Ubuntu falls by one anchor once the A/B framework is scored as unbuilt or the Jetson flavor is counted (lead ≤ 2.0, a tie); (b) NVIDIA adding RHEL 10 or bootc to the K3s column, or the S3 decision choosing RKE2, which removes support 1; (c) Lyrical adding RHEL 10 arm64 at Tier 2.
- **Toward Debian 13 + Rugix:** a Rugix (or RAUC) Jetson integration shown to work on JetPack 7.x, plus OneMind's A/B on Ubuntu still unbuilt by the M1 gate. A shipped, existing framework would then outweigh ROS Tier 1 arm64, which helps only the Pi 5 tier.
- **Strengthening the claim (upheld):** NVIDIA or Canonical shipping a JetPack or Ubuntu-for-Jetson release on **26.04** (the stack becomes a single release, and Lyrical Tier 1 then reaches Jetson); a lab result for OneMind's A/B on 26.04 covering x86, Pi 5 and Jetson with automatic rollback and a power-cut test; #2170238 fixed in linux-raspi for resolute.
