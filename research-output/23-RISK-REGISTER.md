> ### Explain it like I'm the founder
> A risk register is a list of the things that could hurt OneMind, ranked so you look at the worst first. Each row says **how likely** it is, **how bad** it would be, **what we do about it now**, **who owns it**, and the **tripwire**: the specific event that tells you the risk is turning real and it is time to act.
>
> The research raised about 120 separate risk statements across 30-odd files. Many were the same risk seen from different angles (for example "Jetson software ends early", "NVIDIA's kernel isn't LTS" and "Orin modules end in 2032" are one risk). This file merges them into **62 risks**. The map in §6 shows where each original statement went, so nothing was dropped.
>
> **The five to watch first:**
> 1. **NVIDIA's Jetson software dies before your robots do** (RR-01). It has happened to every Jetson generation so far.
> 2. **The Kubernetes upgrade treadmill** (RR-02): a box that sits offline for a year falls behind and can't skip versions.
> 3. **Your own time** (RR-03): labour, not licences, is the biggest 10-year cost, and every "add a second X" decision adds to it.
> 4. **Your current cloud cluster still runs a retired, unpatched ingress controller in public** (RR-04).
> 5. **An AI agent tricked into moving a real machine** (RR-06).
>
> None of these says "change the foundation". Most say "keep the exit cheap and run the test before you depend on it".

## 1. How to read this register

**Likelihood (L)**, over the period the risk applies to (usually 2027–2036):

| Score | Word | Meaning |
|---|---|---|
| 1 | Rare | Needs an unusual chain of events; no precedent found |
| 2 | Low | Has happened elsewhere, but our design makes it unlikely |
| 3 | Medium | Plausible; precedent exists in a comparable product |
| 4 | High | Expected at least once in the period unless mitigated |
| 5 | Near-certain | Already happening, or scheduled by a vendor |

**Impact (I)**, if it happens unmitigated:

| Score | Word | Meaning |
|---|---|---|
| 1 | Minor | Annoyance; fixed in a normal release |
| 2 | Moderate | One feature, tier or SKU is degraded for weeks |
| 3 | Major | A tier is blocked, or months of founder time are lost |
| 4 | Severe | Fielded devices are exposed or stranded, or a market (for example the EU) is closed |
| 5 | Critical | Physical harm, mass compromise, or the company cannot ship |

**Severity = L × I.** Bands: **Critical ≥ 16**, **High 12–15**, **Medium 6–11**, **Low ≤ 5**. Rows are sorted by score, then by impact. **Impact-5 rule:** a risk with impact 5 sits in at least the High band whatever its score (marked ⇧). IDs are stable labels assigned in this order; future re-scores move rows, not IDs. Where a source file rated a risk, this register keeps that rating unless the evidence behind another file's rating is stronger; every change is noted in the row ("rated …in 0X").

**Owner.** OneMind is one person today (M-6), so most rows are owned by **Zeus**. The role in brackets says which hat he wears, and which hire should take the row over: *release eng.* (image, updates, kernel), *platform* (k3s, storage, backups), *security*, *BSP/HW* (boards, hardware line), *ecosystem* (Market, plugins, review), *AI layer*, *business*, *counsel* (an external lawyer, engaged by Zeus), *research lead* (whoever maintains this evidence set).

**Trigger.** The observable event that moves a risk from "watch" to "act". Triggers name a test from the founder test plan where one exists (`22-HARDWARE-LAB-TEST-PLAN.md`; IDs as used in 01 §12) or a scenario trigger from 16 §7 (`TRIG-W15-xx`).

**Links.** Claim IDs, decision-critical questions (`DC-xx`), founder decisions (`Z-xx`, in 26) and the source file. **Req** lists the requirement IDs the mitigation serves.

## 2. Glossary

| Term | Meaning here |
|---|---|
| **A/B update** | Two copies (slots) of the OS. Updates go to the idle copy; if it fails its health check, the box boots the old copy again. |
| **BSP** | Board Support Package: the vendor's kernel, firmware and drivers for one board (NVIDIA's is called L4T / JetPack). |
| **Branch head** | The newest release of a vendor's software line. "Fixes only at branch head" means old releases never get the fix; you must upgrade. |
| **CRA** | EU Cyber Resilience Act: security duties for products with digital elements sold in the EU, fully applicable from 2027-12-11 [C-W6-001]. |
| **db / dbx / KEK / PK** | UEFI Secure Boot key stores: allowed signers, revoked signers, key-exchange keys, platform key. |
| **DKMS** | A system that rebuilds out-of-tree kernel modules (such as NVIDIA's driver) for each new kernel. |
| **ELTS** | Freexian's paid Extended Long Term Support for old Debian releases. |
| **Health-gated commit** | The new slot is only marked "good" after fresh checks pass (k3s up, core pods ready, network reachable). |
| **k3s minor** | A Kubernetes version step such as 1.34 → 1.35; Kubernetes forbids skipping one. |
| **kine** | The layer that lets single-node k3s keep its state in SQLite instead of etcd. |
| **meta-tegra** | The community (OE4T) Yocto layer that builds Jetson images without NVIDIA's Ubuntu. |
| **MOK** | Machine Owner Key: a key a person enrols at the console so a stock kernel trusts extra modules. |
| **PCR** | A TPM register holding boot measurements; disk keys can be "sealed" to PCR values. |
| **PREEMPT_RT** | The Linux real-time patch set (now mainline) that bounds worst-case latency. |
| **sysext / confext** | systemd system and configuration extensions: signed images merged over `/usr` or `/etc` on a read-only OS. |
| **Trigger** | The event that says a risk is materialising. |
| **UKI** | Unified Kernel Image: kernel + initrd + command line in one signed file. |
