# internal/storage: disks, health, mirror state and dry-run plans

**Serves:** `docs/umbrel2/storage.md` epics **STOR-3** (inventory and health collector) and the plan half of **STOR-4** (operation engine); CLI half of **STOR-9**. Decision it builds on: btrfs raid1 inside LUKS2, no ZFS and no parity RAID in v1 (storage.md §4.1, to be recorded in `docs/DECISIONS.md` by STOR-0).

## What it does, in plain words

| Question | Tool it runs | Function |
|---|---|---|
| Which disks are attached, and which may be touched? | `lsblk --json --bytes --paths -o …` | `Collector.Inventory`, `ParseLsblk` |
| Is each disk healthy? | `smartctl --json=c -a` (`-d sat` for USB) | `Collector.Health`, `ParseSmart` |
| Is the data protected? | `findmnt --json`, `btrfs filesystem show --raw`, `btrfs filesystem df -b`, `btrfs device stats` | `Collector.MirrorStatus`, `Evaluate` |
| What would it take to protect it? | none: it computes | `PlanCreate`, `PlanProtect`, `PlanRepair` |

**Nothing in this package changes a disk.** A plan is a list of exact commands plus the safety checks they passed, sealed with `plan_sha256` over the target disks' identity (id, size, serial tail) and the commands, so a swapped disk produces a different hash. In STOR-4/5 an owner approves the plan as a `storage.*` action and `onemindd` runs it from a journal; agents can only request it.

Tools run as separate processes (no linking); all are GPL-family packages in Debian main (versions in the lab notes).

### Disk roles (`Disk.Role`)

| Role | Meaning | May a plan wipe it? |
|---|---|---|
| `system` | holds `/`, `/boot`, `/boot/efi`, `/efi`, `/usr` or swap | never |
| `member` | part of the mounted btrfs set (by filesystem UUID or by member path) | never |
| `in-use` | something on it is mounted | no |
| `has-data` | partitions or signatures, nothing mounted | no (a "use this disk anyway" flow with an explicit wipe is STOR-8) |
| `unused` | blank | yes, after approval |

### Set state (`Mirror.State`)

| State | When |
|---|---|
| `protected` | ≥ 2 members, all present, every Data/Metadata/System profile redundant (raid1, raid1c3, raid1c4) |
| `degraded` | a member is missing; or single-copy chunks remain on a multi-disk set; or the **needs-scrub marker** exists (the set ran degraded and the returned disk may be stale, see the lab finding) |
| `unprotected` | one copy only (single/dup), e.g. a one-disk box |
| `unavailable` | nothing mounted at the path, or not btrfs |
| `unsupported` | raid5/raid6 found (never generated by OneMind) |

`Mirror.Repair` lists what `PlanRepair` would do: `reconnect` (a person), `scrub`, `soft-convert`.

### Health verdicts (`Health.Verdict`)

`critical`: SMART failed (or exit bit 3), a prefail attribute at threshold (bit 4), NVMe critical-warning flags, spare below threshold, wear ≥ 95 %, temperature ≥ 70 °C. `warning`: wear ≥ 80 %, temperature ≥ 60 °C, NVMe media errors, ATA reallocated/pending/uncorrectable sectors > 0. `unknown`: no SMART (virtual disks, some USB bridges). Thresholds are `DefaultThresholds`; vendor temperature limits from `nvme id-ctrl` and the alert rules come with STOR-6. A `critical` disk blocks any plan that would write to it.

### Plans

| Plan | Use | Steps (abridged) |
|---|---|---|
| `create` | new set on blank disks | per disk: `sgdisk` GPT + partlabel `onemind-data` → (`--encrypt`) `cryptsetup luksFormat --type luks2` + `open` → `mkfs.btrfs -d raid1 -m raid1` (raid1c3 metadata at 3+, single/dup for 1 disk with a warning) → mount → subvolumes `@`, `@storage`, `@snapshots` |
| `protect` | add a disk to the mounted set (1 → 2 is "protect", n → n+1 is "add") | prepare as above (encrypted when the set is) → `btrfs device add` → `btrfs balance start -dconvert=raid1,soft -mconvert=…,soft` |
| `repair` | after a missing member is back | `btrfs scrub start -B` → soft-convert balance → `btrfs device stats --reset` → remove the needs-scrub marker |

Checks that block a plan: disk exists and is listed once; not `system`; `unused`; not read-only; SMART not critical; (protect) no missing member, no raid5/6, the new disk can hold what is already allocated; (repair) every member present.

## CLI

`cmd/onemind/storage.go` (read-only; `smartctl` needs root):

```
onemind storage disks  [--json]
onemind storage health [--json] [DISK...]
onemind storage status [--mount DIR] [--json]
onemind storage plan create  --device DISK [--device DISK...] [--mount DIR] [--encrypt] [--key-file F] [--json]
onemind storage plan protect --device DISK [--mount DIR] [--key-file F] [--json]
onemind storage plan repair  [--mount DIR] [--json]
```

## Wiring (recorded here, not applied)

`cmd/onemind/main.go` is shared with other streams, so this branch does not edit it. To register the command, the CLI owner adds **one case** to the `switch` in `run` and appends the usage text:

```go
	case args[0] == "storage":
		err = storageCmd(args[1:], stdout)
```

```go
const usage = `usage:
  ...
  onemind version
` + storageUsage
```

The lab built exactly this with `go build -overlay` (a patched copy of `main.go` outside the repo), and `go test -overlay … ./cmd/onemind` passes with it. Until it is registered, `storageCmd` is exercised by `cmd/onemind/storage_test.go`.

`cmd/onemindd/main.go`: no change in this slice. STOR-3's heartbeat `storage` object (state, free bytes, alerts) needs the contract field from STOR-0 first; then one line in `onemindd` calls `storage.New().MirrorStatus(ctx, "/data")` on the heartbeat tick.
