Rename the box (P-05). The owner can change the box's name from Settings > About (Rename this box) or with `onemind name set NAME`; `onemind name show` prints it. The request is `PUT /v1/instance/name`, which files an `instance.rename` action that waits in Approvals: an agent or the CLI can ask, only an owner approves (D-027). Once approved, the host service (new kind `set-hostname`) saves the name on the data partition (the root is read-only), starts the new onemind-hostname.service to switch the running name (the host service's own sandbox has a private host name, so it cannot), fixes the 127.0.1.1 line and restarts avahi, so the box answers as NAME.local at once; at every boot `onemindd host apply-hostname` (a drop-in of onemind-data-layout.service) puts the name back before avahi starts. The first rename also pins the Kubernetes node's name (K3S_NODE_NAME in /data/onemind/etc/k3s.env, read by k3s.service and the health gate), so a rename never turns the next boot into a new node that the local-path volumes do not belong to. The name is one lower-case DNS label, as the first-run setting already requires. Tests: Go unit tests for the host kind, the saved name, boot apply and the node pin; gateway tests for the owner-only approval, idempotent replay, refused names and the sign-in name following only a finished rename; CLI and dashboard tests; QEMU first-boot checks F21 (the rename reaches the running system and avahi) and F22 (it survives a reboot), pre-registered in CRITERIA-FIRSTBOOT.md section 15 (F13 and F14 before the round-2 integration renumbering). The host also restarts the gateway a few seconds after the answer is journaled. HTTPS keeps the names the box CA was made with: the CA's critical name constraints are fixed for its life, so a rename never moves the certificate's names (the gateway, the first-boot `onemind_starting.py` and the join URL default read the CA's own box name, and `BoxCA` now checks names against the CA on disk), and the certificate does not flip between name sets. Because avahi publishes only the host name, the new onemind-mdns-aliases.service (`onemindd host mdns-aliases`) keeps publishing `onemind.local` and the previous name as aliases from /data/onemind/etc/mdns-aliases, so passkeys, saved links, join codes and the apps keep working. A rename that fails after the name was saved puts the saved name, the alias list and the hosts line back (and sets the running name back), so the next boot never applies a name the owner was told failed; an avahi restart failure after the box really changed name is only logged. A failed rename restores only the display name, not other first-run settings saved meanwhile. Known limits, each a follow-up: `https://<new>.local` needs a CA-rotation design (it is not in the certificate); app hosts under `<app>.<new>.local` are likewise not covered; the phone app's box-settings screen still only edits the stored name, not the host name.
