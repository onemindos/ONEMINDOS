Rename the box (P-05). The owner can change the box's name from Settings > About (Rename this box) or with `onemind name set NAME`; `onemind name show` prints it. The request is `PUT /v1/instance/name`, which files an `instance.rename` action that waits in Approvals: an agent or the CLI can ask, only an owner approves (D-027). Once approved, the host service (new kind `set-hostname`) saves the name on the data partition (the root is read-only), starts the new onemind-hostname.service to switch the running name (the host service's own sandbox has a private host name, so it cannot), fixes the 127.0.1.1 line and restarts avahi, so the box answers as NAME.local at once; at every boot `onemindd host apply-hostname` (a drop-in of onemind-data-layout.service) puts the name back before avahi starts. The first rename also pins the Kubernetes node's name (K3S_NODE_NAME in /data/onemind/etc/k3s.env, read by k3s.service and the health gate), so a rename never turns the next boot into a new node that the local-path volumes do not belong to. The name is one lower-case DNS label, as the first-run setting already requires. Tests: Go unit tests for the host kind, the saved name, boot apply and the node pin; gateway tests for the owner-only approval, idempotent replay, refused names and the sign-in name following only a finished rename; CLI and dashboard tests; QEMU first-boot checks F13 (the rename reaches the running system and avahi) and F14 (it survives a reboot), pre-registered in CRITERIA-FIRSTBOOT.md section 9. The host also restarts the gateway a few seconds after the answer is journaled, so the box certificate and the join QR carry the new name (the gateway reads the saved name before ONEMIND_NET_BOX_NAME). Known limits, each a follow-up: the phone app's box-settings screen still only edits the stored name, not the host name; ONEMIND_FABRIC_HUB_URL, written once at first boot, still names the old `<box>.local`, so new join codes carry it until first boot rewrites it; and `onemind.local` stops answering after a rename because avahi publishes only the host name, so `<name>.local` is the way in.
