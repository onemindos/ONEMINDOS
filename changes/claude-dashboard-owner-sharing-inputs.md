Owner screens for app sharing and agent inputs (issue 1214). Settings, Permissions now lets an owner change who can open an app (teens, children, guests and people by name, and whether people sign in with OneMind or the app's own sign-in) and what an agent reads outside OneMind (web pages, email, files, a chat host, and the recorded accepted-risk list). A change that adds power, sharing with more people or declaring that an agent reads less, is confirmed in place through the SDK's shared step-up helper: the hub names the step-up, the browser asks for the proven key, and before the box's first proven key also for the code on the box's own screen; taking access away goes through at once. An agent nobody has declared yet starts with everything ticked, so saving never loosens it by accident. The CLI gets onemind apps access get and set (flags left out keep their value, --json), which narrows directly and, for widening, says to confirm in the dashboard; onemind agents inputs set now points there too. The gateway documents the answer of apps.access.get and set as the AppAccess schema in the OpenAPI spec so the dashboard reads it through generated SDK types; responses are unchanged. The app page's Access tab links to the new editor. Moving an app from OneMind's sign-in to the app's own now counts as widening, so it asks for the same step-up as sharing with more people (OneMind no longer checks who opens it); going back to OneMind's sign-in needs none. GET /v1/users documents its answer as the UserInfo schema, so the sharing editor reads people through generated SDK types; the answer is unchanged. A save refused because the sign-in lapsed now signs out instead of showing a note.
