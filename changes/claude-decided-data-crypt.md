Encrypted data, slice 1 of IMG-05 (#152), built on the founder's disk-encryption decision of 2026-11-22. On a box's first boot a blank data partition now gets btrfs instead of ext4, with three subvolumes: @ (the default one, which is what /data mounts), @storage (files) and @snapshots (for a later snapshot step). A box with a TPM puts that btrfs inside LUKS2 and unlocks it by itself after every restart; its recovery key is shown once for the emergency kit. A box without a TPM (a Raspberry Pi 5, for example) stays unencrypted so it can come back by itself after a power cut, unless the owner boots it the first time with the kernel command line word onemind.data_encrypt=passphrase: it then asks twice on the console for a passphrase, of at least 8 characters, that will be typed at every restart, and still makes a recovery key. The passphrase and keys only ever go to cryptsetup on stdin, never on a command line or into the journal. The random first key's slot is now really wiped (cryptsetup checks the key against the other slots, so the recovery key is given on stdin). /etc/fstab mounts /data as auto, so ext4 boxes installed earlier keep working and are never converted. btrfs-progs is added to the Debian package list. The setup-screen wording waits for PR #921 and the QEMU battery cases (power cut, passphrase unlock) wait for PR #837.
