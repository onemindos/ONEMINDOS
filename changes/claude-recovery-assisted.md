Contact-assisted recovery and the remote wait (gateway permissions 25e, D-028). Start through the gateway API or `onemind recovery start`. A contact confirms with a signed matching number or an offline 8-digit code. A request accepts up to three submissions and closes after three wrong answers. An owner can start one contact request per day. After confirmation, the owner waits 24, 48 or 72 hours, with a 72-hour minimum if they used a strong key in the last seven days. Finishing requires the owner's current password as independent proof. The CLI can finish contact-assisted recovery by changing the password. A WebAuthn client can use the gateway API to enrol a new passkey, change the password, or both. Losing the current password requires another recovery path, such as the printed kit at the box.

Remote recovery starts with a password and authenticator code or, through the API, an existing passkey. It waits 72 hours or seven days and finishes by enrolling a passkey through the gateway API with a WebAuthn client. The dashboard sign-in flows are scheduled for 25i. Running recoveries appear under Settings, Account with a Stop button and wait settings. The request starter, a full owner credential, or a recovery contact for the account can stop a request. A confirming contact's revocation prevents later credential writes. Security notices at start, confirmation, during the wait and at the end are queued with the recovery change and retried after a dispatch failure or restart. The CLI stores recovery credentials with their originating gateway.
