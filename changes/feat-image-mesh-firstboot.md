First boot of the OS image now sets a box up and joins it to the mesh the way deploy/install.sh does (IMG-MESH-01, #292). A hub makes one box CA with the gateway's own code (no second openssl CA), gives its hub NATS loopback-only clients with a service nkey each and a leaf port on the mesh address that needs a box-CA client certificate, and turns on HTTPS, mDNS and fabric joins in the gateway. A new onemind-mesh-setup unit then starts Headscale, lets the hub join its own mesh with a one-time key minted over the local socket, issues the NATS leaf certificate and gives the gateway its Headscale API key, on every boot and skipping what is done; neither key reaches the journal or the console. Workers and leaves no longer use a shared NATS password: onemind.conf, the seed, the setup wizard and the USB installer take the join code from onemind fabric ticket (join_code, optional hub_addr), and a new onemind-fabric-join unit runs onemind fabric join so the owner approves the box on the hub. The old keys hub, join_token and nats_tls are refused; boxes set up before keep running and get a note that moving them onto the mesh means reinstalling. Image battery criteria F7 to F9 are pre-registered and implemented (mesh address and HTTPS with the box CA, Headscale refusing a made-up key, NATS refusals, one CA) and pass under KVM. A hub on a LAN without a router (an offline network, or the test VM's isolated one) takes its single LAN IPv4 address when there is no default route, instead of failing mesh setup.
