Every release now carries the phone app. A new android job in the release workflow (no trigger change, still behind the F-27 gate and the release environment) builds the Android APK from the commit the released image was built from, but only after scripts/release/check-image-run.py proves that image run is this repo's own successful push or manual image.yml run and its commit is on main or release/next (a run started by a pull request, fork PRs included, never reaches the upload key); with the version stamped to the release and the upload key from the secrets store; it refuses to run without the signing secrets, so no debug-signed app is ever released. The run check, the version stamper and the new scripts/check-apk run from the workflow's own checkout, never from the commit being released; check-apk refuses an APK whose package is not com.onemindos.*, whose version is not the tag, that is debuggable or debug-signed, or whose bundle still carries the demo-data module. The publish job attaches onemind-VERSION.apk, its SHA-256 file and a signature of that file made with the release key (scripts/release/apk-assets.py, verified before upload), tags the release at the same commit and links the Android install guide in the notes.
