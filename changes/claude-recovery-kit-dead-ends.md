The printed emergency kit no longer leaves an owner locked out (D-028, gateway audit items 25a to 25c). The kit now also carries the disk (LUKS) recovery key when the data disk is encrypted: the kit step reads it from the storage service (the node keeps its copy until the owner confirms the kit, so a closed tab or a dropped connection loses nothing), prints it, and the gateway never stores it (the general recovery key route stays off, which settles F-61 and F-62 for this one path). Later kits and the kit status name, without secrets, the kit page that holds the disk key, so a thrown-away page is noticed. A kit can be issued with no backup destination; a destination added later is listed as not covered until a new kit is issued, and a new kit adds its key beside the old one, so older snapshots stay openable; every re-issue raises a warning event. An owner who lost every passkey no longer hits the rescue console dead end: the terminal page takes the owner recovery key from the printed kit, and the gateway accepts it only from the box itself (loopback, no proxy headers), checked against a salted full hash and not the public fingerprint, with a timed lockout that doubles after 5 wrong tries, cannot be raced, and never deletes anything. onemind recovery kit issue --out opens the file before it asks for a kit, so an existing file issues nothing. The kit screens show the disk key and where it is, first run offers the kit without a destination, and onemind recovery kit status and issue are added.
