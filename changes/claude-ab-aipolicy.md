aiPolicy enforcement for agent reads of app data (Refs #165): one deny-by-default rule in ai_policy.py decides whether an app's data may reach an AI agent, and both agent surfaces call it before any app data leaves. A plugin tool's output (the app's own data) is withheld from MCP get_action, list_actions and onemind://actions/{id} and from REST GET /v1/actions, GET /v1/actions/{id} and an idempotent replay of a tool call, and an agent may not run a plugin read tool at all (403, reason ai_policy, the backend is never called), unless the app's aiPolicy is allowed (no policy, display-only, prohibited, consent-required, official-mcp-only and unknown values all withhold it; the owner still sees the output). The REST agent filter and the MCP catalogue now read the policy through the same helper. GET /v1/apps carries aiPolicy (null when none is declared, unknown for a value the gateway does not know), MCP list_apps and get_app show the same value, and onemind apps list adds an AI column while onemind apps info says what the policy means.
