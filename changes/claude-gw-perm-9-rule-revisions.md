Standing approvals grow the limits the founder chose (F-10, D-028): a rule lasts 30, 90 or 180 days (the cap moves from 90 to 180) or forever, forever only for read and write types and never with accept-injection-risk; "end if unused for 14 days" is on by default; max_uses ends a rule after that many uses (1 = once more); bytes_per_day and items_per_day cap what its uses write; notify_after is each, digest or silent (silent for read-only rules); a target limits it to resource paths (a request outside them, or one that climbs out with "..", is not covered). Rules can now be edited: PATCH /v1/approval-policies/id makes a new revision, narrowing applies at once and widening needs a fresh passkey. Revoke is one step with no passkey (POST revoke, revoke-all for one agent). A rule is suspended, not deleted, when its agent's token is rotated, revoked or re-minted, the agent starts reading outside text, the owning person's role changes, or a request turns out riskier than its type; POST reconfirm (one passkey tap) binds it to the agent's current identity again. Forever rules get a review reminder every 90 days that ends nothing (POST keep). Until gateway permissions PR 11 brings the proven key (L2) that D-028 requires for any Forever rule, creating a Forever rule or widening a rule to Forever is refused with 409 needs_proven_key, the same way accept-injection-risk is. onemind permissions rules list, revoke, narrow, reconfirm and keep. The two automation docs now state the D-028 caps. Gateway permissions design PR 9, F-10, D-028.
