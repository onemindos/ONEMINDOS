Phone hardware approval key, Android first (Refs #703): a new local Expo module, mobile/modules/onemind-approval-key, makes an EC P-256 key in the Android Keystore (StrongBox when the phone has one) that needs strong biometrics for every single use, never accepts a PIN or pattern, and is invalidated when a new finger or face is enrolled. The Approvals screen can set the key up (registered with the hub through the approver-keys routes of #702) or remove it, and once it is set up every approval is signed inside the system biometric prompt, which names the action and plan. The phone refuses to sign a changed plan or a payload that differs from the card, never signs the same challenge twice, and verifies the signature against its own public key before sending, so a replayed signature or a bare success flag never reaches the hub. A refused key on a destructive or actuate approval (F-2) falls back to the passkey, and a key killed by a new enrolment is revoked and set-up is offered again. USE_BIOMETRIC is no longer blocked in app.json. The iPhone Secure Enclave half follows.
