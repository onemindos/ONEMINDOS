Browser apps (Firefox and Chromium on Neko) now open in a desktop window with a profile for each person (#692). A manifest marks a browser with `spec.browser.profileVolume`. The app's own Deployment is only a template that runs nothing. The first time a person opens the browser, the gateway gives them their own claim `profile-<key>`, Deployment and ClusterIP Service `browser-<key>`. `<key>` is a one-way hash of the person's id. `POST /v1/browsers/{app_id}/session` and `.../session/close` start and stop that pod; closing keeps the profile. The proxy serves `<app>--<key>.<box domain>` only to the person whose key it is. Any other person, an agent or the shared template gets 403, and a request without sign-in gets 401. `POST /v1/browsers/{app_id}/profile/reset` files `browser.profile.reset`, and nothing is erased until an owner approves it. Only a signed-in person can call these routes: agent and API tokens are refused. The dashboard opens browser apps at `/browser/<id>` in a window that frames the stream and has Close and Reset profile buttons. The dashboard page allows framing only box subdomains, and only while a browser app is in the catalog.
