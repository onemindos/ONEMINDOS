Firewall: view (P-09 part 1, refs #239). `GET /v1/network/firewall` (owner only, read only) returns the box's live nftables rules in a checked, structured form: the host service runs `nft -j list ruleset` and the gateway re-checks every field, works out who each rule lets in (this box, the mesh, the apps on it, the home network, or any address) and writes one plain sentence per rule. It answers the headline question directly (`exposure`: never the internet, open to the internet, not protected, or not fully checked) and lists any service open to any address. The Network screen has a new Firewall section, and `onemind firewall show` prints the same words. An unreadable firewall is reported as unknown, never as safe. Nothing can be changed yet: allow rules with automatic revert are part 2 (the API and CLI carry `editable: false` and have no write command). A rule it cannot read that could let strangers in, a ruleset cut for size, or an entry that failed a check turns the answer into "not fully checked" instead of "never the internet". Only plain replies (`ct state established,related`) count as replies; `0.0.0.0/0` and a public interface name count as the internet. Tested against the real `nft -j list ruleset` output of the shipped host.nft. The host service cannot run nft itself (the kernel wants CAP_NET_ADMIN even to read nf_tables, and the host service deliberately has none), so a new root-only socket, `onemind-firewall-read.socket`, starts a one-shot reader that holds only that capability and can only print the ruleset. Set members that nft prints with a comment or timeout are read, anything unreadable is counted as not fully checked, and a named set that holds everyone (`0.0.0.0/0`, or the two halves of the internet) counts as the internet.
