SSH keys and the SSH switch, from the owner's own screens (wave 2, P-06; stacked on the owner shell, #1099). The gateway has GET /v1/ssh and GET /v1/ssh/keys (owner only) and three owner actions through the approval queue: POST /v1/ssh/keys (add a key), DELETE /v1/ssh/keys/{id} (remove one) and PUT /v1/ssh (SSH on or off). Agents cannot ask for any of them; adding a key and switching SSH on need a passkey once passkeys are active, taking exposure away needs none. The gateway checks the public key (plain, a supported type, RSA at least 2048 bits) and shows its fingerprint on the approval card; the host service files one text job on the data partition and starts a new root oneshot, onemind-ssh-apply.service, which runs onemind-owner (new key-rm, ssh-on, ssh-off, apply-job; it never follows a symlink as root). Off is a flag file on /data that ssh.service tests, so it holds across reboots and updates. The ssh firewall chain now counts new connections per address and drops more than 6 a minute before sshd sees them. The dashboard Account page has an SSH keys card, and the CLI has onemind ssh-key add, list and rm, and onemind ssh on, off and status. First-boot check F20 (criteria pre-registered first) adds a key, removes a key and switches SSH off and on through the real approval path.

Second review fix: on the cloud boards, port 22 now goes through the same SSH chain as everywhere else, so the 6-new-connections-a-minute limit also covers the internet and port 22 closes when SSH is switched off. The SSH screen and the CLI no longer say "home network only" for a cloud box.
