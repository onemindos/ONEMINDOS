Known USB radio dongles now get stable names (issue 732). The image ships udev rules that name a Home Assistant Connect ZBT-1 or ZBT-2, SONOFF Zigbee Dongle Plus (P and E), ConBee II or III, or a Heltec WiFi LoRa 32 V3 `/dev/onemind/<kind>-<usb port>` (kind `zigbee`, `zigbee-thread` or `lora`) and hand it to the new `onemind-radio` group (mode 0660). A dongle is matched by its USB vendor and product id and its product string, because cheap USB-serial chips share one id across many products; the Heltec V3 is recognised only by its CP2102 chip's default string, and its card says so. The rules are rendered from one table, `sdk/schema/onemind.radios.json`, which the node agent and the gateway also read. The node agent reports each name udev made as a radio in its heartbeat, only while the link still points at that USB port and device. The gateway shows a radio-found card for every USB serial line on every machine at GET /v1/radios (nodes:read, so a child cannot read it), with kind, model, port and stable name, and `onemind radios` prints them. Any other USB serial device is listed with no kind and no name, and can never be granted. Unplugging a dongle removes its card with the next heartbeat.
