Desktop apps from Flathub (#1097, D-026, D-027). Debian 13 packages Flatpak, so OneMind builds none of it. The image now ships flatpak with one system installation on /data (so the read-only root is untouched and apps survive a reboot and an A/B update). The host service gets calls to search Flathub, install, update, remove and launch; every install writes the same sandbox (no host files, no home folder, no way back out to the box, one granted folder of its own that removing the app keeps). The gateway adds desktop.app.install, desktop.app.update and desktop.app.remove: an owner or an agent may ask, only an owner approves, and a request that could not run is refused instead of filed. New routes: GET /v1/desktop-apps, GET /v1/desktop-apps/search, POST /v1/desktop-apps/{app_id}/launch. The dashboard has a Desktop apps screen and the CLI has onemind desktop-app list, search, install, update, remove and launch (install, update and remove only file the request). The desktop base image carries flatpak and the script that runs the app an owner opened on the streamed screen. Not in this change: the desktop-apps Neko app that mounts /data/onemind into a pod and streams the session, and the real Obsidian check (lab kit LT-FLATHUB-01).

Review fixes (#1142): the granted folder is now made inside a transient systemd-run unit that has CAP_CHOWN (the host service has none, so the old in-process chown made every install fail and roll back), the app folder is root 0755 and the granted folder 0755 owned by the desktop user so the runtime and Files can reach it, and no symbolic link is followed. The sandbox now resets every filesystem grant (`--nofilesystem=host:reset`, Flatpak 1.14 or newer, exact first version UNVERIFIED) and removes the session bus, system bus, ssh-agent, smart card, printing and gpg-agent sockets; the desktop pod points Flatpak's user directory at an empty read-only folder so no per-user override can widen a sandbox, and ships the same `onemind` installation file as the box. The flatpak and folder units are hardened (kernel, cgroups, clock, devices, address families, capability set). The session script no longer uses the non-POSIX `-nt` that the CI shellcheck rejects. Update checks are cached for ten minutes and cover runtime-only updates, unused runtimes are removed after an update or removal, and the approvals screen shows what Flathub says an asked-for app is.
