Every machine now reports one hardware profile (NodeCapabilities, issue 618) in its heartbeat: the data disk (SSD or not), memory and whether it is unified, accelerators (NVIDIA, AMD and Intel GPUs, Intel NPU, Hailo, the Jetson GPU) with VRAM, compute capability and driver, USB devices by vendor and product id, serial lines, Wi-Fi, Bluetooth and cellular radios, USB and CSI cameras, power source and thermal state. It is read from sysfs and /proc (nvidia-smi only for VRAM), every field is a value or null for unknown, never a guess, and no serial number, MAC or IP is included. The gateway serves it on GET /v1/nodes under nodes:read (a child cannot read it), the API contract and SDKs describe it, and `onemind node capabilities` prints it for this machine. VM device grants, radio detection, edge model fit and app verdicts read this one document instead of probing again. Every `device` is a full /dev path, vendor:product ids are `id`/`pci_id`/`usb_id`, and each accelerator also carries its PCI address (`pci_slot`) so a VM grant can tell two identical cards apart. The gateway serves a profile only if it validates exactly against the contract (no extra fields, pinned device paths and id formats); a malformed or planted profile is dropped and the heartbeat kept.
