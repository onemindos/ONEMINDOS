The whole-box restore drill (test/restore-drill) now runs end to end on a KVM machine and restores the system snapshot instead of only checking it is there. The clean box gets the old box's name, installs, then puts back /etc/onemind, the gateway database and audit log, and k3s's own datastore, token, CA and credentials, restarts them, and the drill reads canaries back (a ConfigMap only the old datastore knew, the old install action in the gateway database and the audit log) before the app's volume and database come back. A run can only pass if those system checks passed, and it still fails when the restore clock goes over 3600 s. Harness fixes found by the real run: the system disk gets bootindex 1 (with the empty backup disk present the guest never booted), faster guest disk cache, one retry when the gateway's first cold start is slower than the installer's 60 s wait. Four product gaps that stop any app with a database from installing and backing up under the hardened gateway are worked around in the harness and marked in the results (db_rbac_workaround), not hidden. A real timed run on a KVM host passed in 269.4 s of the 3600 s budget. A fifth gap (an app's default-deny network policy has no path to the shared PostgreSQL) is also worked around and marked (db_netpol_workaround).
