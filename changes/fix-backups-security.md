Security fixes from the review of #86 (backups). **Restore of one path no longer follows symlinks:** the agent opens every folder on the way one step at a time without following symlinks and writes only through the folder handle it holds (openat, renameat, unlinkat), so an app that swaps a folder for a symlink while root restores cannot redirect the write into another app's volume or the k3s datastore; directory restores stage in a root-only folder and are copied in through the same handle; the gateway now stops the app for the duration of a path restore. **Database dumps are private:** the dump folder is 0700, the file is created under umask 077 (0600) before pg_dump fills it, and a failed dump deletes its temp file. **No files-only restores for database apps:** a snapshot that lacks the app's database dump is refused before anything is swapped (agent field strict_files, set by the gateway). **The unsigned loopback POST /api/v1/backup/run is removed** (nothing called it; runs only come as gateway-signed jobs). **Cold backups** record each app before scaling it down, so a failure part-way still scales every stopped workload back up. Follow-ups not done here: egress to onemind-db:5432 from app namespaces, per-role CONNECTION LIMIT and pg_hba, routers/backups.py destination URL checks (urlsplit, userinfo, link-local), backup status leaking destinations to agents and adults, expiry for _pending_secrets, an attempt limit on kit confirm, uninstall removing the systemd drop-in directory with rm -rf, and the app-restore swap (swapDir, swapFile) still resolving paths by name (safe only because the gateway stops the app first).
