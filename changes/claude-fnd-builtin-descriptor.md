Built-in app descriptors and their conformance test. A new schema, sdk/schema/onemind.builtin.schema.json, is the built-in profile of the one App manifest (apiVersion onemind.app/v1, kind App, file onemind.app.yaml) and says what each built-in plugs into (routes it owns and calls, search provider, share types, notification topics, map layers, cards, actions, settingsPages, backup units, data classes, phone entry). No block reuses an App spec name with another shape: spec.backup.units is added to the App schema (built-in apps only, it needs spec.system), Settings pages are spec.settingsPages, and a test keeps it that way. The gateway reads core/onemind_core/ID/onemind.app.yaml only for ids on the signed list and builds the request-only MCP tools, the settings pages and the backup set from the switched-on ones (new GET /v1/builtins, marked provisional in the OpenAPI: it folds into the planned GET /v1/surfaces). One gateway gate answers 409 app_disabled for every HTTP and websocket route a switched-off built-in owns, public ones included, but only to a caller it signs in (a made-up credential gets 401), and removing any system id is 409 for owner, CLI and agent even when it has no catalog entry. The signed list grows to Updates, Backups, Notifications and Photos; Updates, Backups and Notifications join the never-off set. A conformance test fails CI when a built-in loses its backup units, calls a route missing from the public OpenAPI, names an unknown table, action or event, or owns a prefix another built-in owns.
