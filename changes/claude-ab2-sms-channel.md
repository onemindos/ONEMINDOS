SMS alert channel (#869): a new sms channel kind sends a short text through a provider-neutral adapter (send(to, text) returns a receipt; adapters register by name; the first one speaks plain HTTPS to the send URL the owner types, as JSON or form fields with a bearer token or basic auth, so no provider SDK or provider name is in the code). The owner's provider token is sealed in the notify secret store and never appears in config, logs, audit or the channel listing. A text carries only the alert title and a hint to open OneMind, never the body. The gateway counts a per-channel hourly limit (default 5, then one summary) and a daily cap (default 20 a day) that counts every attempt to reach the provider, written before the request goes out, so retries, 5xx answers and timeouts the provider may already have billed all count and the cap is checked again before each retry: over the cap a delivery is dropped with a ledger row and a notify.delivery.dropped audit entry, and nothing is sent. Each SMS channel also has a minimum severity (default warning), quiet hours apply as for every channel, and a test send shows the provider receipt or the plain error and counts toward the cap. Reachable through the existing channel routes (POST /v1/notifications/channels with kind sms, POST /v1/notifications/channels/{id}/test, whose answer now carries the receipt); the CLI and the Settings screen follow in a second PR on the same issue. CI uses a fake provider only; the founder types the real credentials at the B2 checkpoint.
