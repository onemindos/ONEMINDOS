Wave 2 setting P-08: an owner can give a cable interface a fixed IPv4 address, gateway and DNS, or go back to DHCP, and a wrong address can never strand them. PUT /v1/network/{iface} only files an owner action (an owner approves it with a passkey; agents and the CLI cannot). After approval the host service asks NetworkManager to make the change inside a checkpoint with a rollback timer (10 to 600 seconds, default 120): the owner opens the box at the new address and presses Confirm (POST /v1/network/{iface}/confirm), and without that NetworkManager puts the old settings back by itself. A change that was still waiting when the box rebooted is put back at the next start. Confirmed changes live in the NetworkManager profile on /data and survive reboots and A/B updates. The Network screen gets a form, a countdown and a Confirm button, and the CLI gets onemind network set, dhcp and confirm. Tests: Go (netset, host routes, CLI), Python (gateway, passkey step-up, refusals), dashboard, and QEMU checks NS1 to NS3 in the first-boot battery (criteria pre-registered in test/qemu/CRITERIA-NETWORK-SET.md). A change whose put-back failed (for example NetworkManager is not up yet) stays pending and is retried instead of being recorded as rolled back; IPv6 DNS servers are refused up front; profiles are addressed by UUID. The host service also settles a pending change by itself every 10 seconds, so the way back never waits for somebody to open the Network screen (for example after NetworkManager restarted, or when it was not up yet at boot); an owner's confirmation is recorded before the checkpoint is destroyed, so it is never undone later; a change whose current settings cannot be read is refused; reading the Network screen never waits behind a change in progress. `onemind network set` without `--dns` works, and `onemind network show` sits in the same `network` command.
