Makes the factory reset work on the new btrfs data layout (stacked on #975). A box with a TPM now gets the OneMind LUKS2 token (id 30) written at first boot, so the reset finds its encrypted data disk. A box without a TPM keeps plain btrfs, and the reset now accepts exactly that case (system disk, GPT name and btrfs label onemind-data), tells the owner the data is not encrypted, and clears the signatures and the first 16 MiB. A foreign disk is still never listed or wiped. The wipe also zeroes the head so first boot makes a fresh data disk. The storage plans and the STORAGE-ACT patch notes now describe the layout @ at /data, @storage at /data/storage and @storage/.snapshots, with set-default @. Fix round after review: the reset now works end to end on a box that has its data disk open. The data-encrypt unit leaves the disk alone (no unlock, no format) while a reset is armed on the ESP, so no TPM or passphrase unlock ever opens data the owner asked to erase. The wipe closes any open LUKS mapping before erasing and refuses when the disk is mounted. After a successful wipe the box restarts so the next boot formats the blank partition (plain boxes too). A retry after a power cut treats an approved partition that is already blank as erased and zeroes its head. New pre-registered QEMU criteria R1 (plain box) and R2 (encrypted box with a software TPM) arm a reset on a real image and check the fresh first boot.
