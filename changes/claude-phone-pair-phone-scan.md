The phone app pairs with a box from its join QR (issue 716). Connect gets a camera scanner and a typed code field for onemind-join:v2, read with the same parser as the sdk (a byte-identical copy, checked by a test). The phone tries the hub address, then the mdns name, then the outside address; the first one that serves the box CA whose sha256 is in the code, under a TLS chain that verifies to that CA, is pinned in the secure store. On Android a new local module (modules/onemind-box-trust) makes the app's own HTTPS (OkHttp) trust that one CA, so there is no certificate warning and no CA install in the phone settings; the system CAs still apply first. On iPhone, and any build without the module, nothing is pinned and Connect says so: only the phone's own trust store checks the box. The phone shows the same short code as the box and finishes with passkey sign-in or the enrolment code the owner made. Plain http codes, a different CA, an expired enrolment code and a code already used on this phone are refused before anything is sent. Device requests use /v1/me/devices when the hub lists it, else the older route. The camera permission has no microphone or audio.
