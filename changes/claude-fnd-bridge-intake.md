Bridge intake (#610): outside data now comes in one way, POST /v1/bridges/<id>/events. Only the bridge's own installation token may post, and only under its own app id; the token carries the new grant events:write:own, minted at an approved install whose manifest has a spec.extensions.bridge block (a manifest cannot ask for it by name). Each event is checked against the bridge's emits, its size limit (at most 16 KiB) and the datapoint envelope, stamped with the app id as source and the provider's licence from the terms record, deduped by id and revision, coalesced latest-wins and kept as the latest value per entity. It is published best effort on the bridge's intake subject onemind.plugin.<id>.in.<kind>.<name> (assets also on onemind.asset.<class>.<id>.<field> and in the asset-state KV bucket); NATS down never fails the caller. Each bridge has a token bucket from its manifest limits, capped by the hub maximum (ONEMIND_BRIDGES_*), plus one hub-wide bucket, so a flooding bridge gets 429 while approvals still arrive at once. Refused events go to onemind.plugin.<id>.reject; 20 refusals in 5 minutes pause the bridge with one owner alert until an owner resumes it. Show-only provider terms keep nothing. Owners and adults read state and counters with onemind bridge list and onemind bridge status; values (GET /v1/bridges/<id>/latest) also pass the bridge's data class check (public data for adults, everything else owners only); onemind bridge resume is owner only.
