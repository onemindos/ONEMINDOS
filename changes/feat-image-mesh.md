IMG-MESH-01 (#292), image build half: the OS image now carries the mesh. Pinned, sha256-checked Tailscale 1.104.6 (`tailscale`, `tailscaled`) and Headscale 0.29.7 binaries are fetched in the `onemind-fetch` stage (same pins as `deploy/pins.env`, plus the hash of each extracted binary); the build creates the `onemind-nats` (962) and `onemind-headscale` (963) users; `/var/lib/tailscale`, `/var/lib/onemind-headscale`, `/var/lib/onemind-nats-leaf` and `/etc/hosts` are bind mounts from `/data/state` (hosts seeded from `/usr/lib/onemind/hosts.default`); and the disabled units `tailscaled` (no log upload, box-CA trust, flannel guard), `onemind-headscale` and `onemind-nats-leaf` ship in the image, with `nftables` added to the package lists. First boot (a separate change) starts them. The recovery data check now also waits for the new bind mounts (and the test escapes "-" in mount unit names). A unit test checks the pins, mounts, users and units against each other.

First boot of the OS image now sets a box up and joins it to the mesh the way deploy/install.sh does (IMG-MESH-01, #292). A hub makes one box CA with the gateway's own code (no second openssl CA), gives its hub NATS loopback-only clients with a service nkey each and a leaf port on the mesh address that needs a box-CA client certificate, and turns on HTTPS, mDNS and fabric joins in the gateway. A new onemind-mesh-setup unit then starts Headscale, lets the hub join its own mesh with a one-time key minted over the local socket, issues the NATS leaf certificate and gives the gateway its Headscale API key, on every boot and skipping what is done; neither key reaches the journal or the console. Workers and leaves no longer use a shared NATS password: onemind.conf, the seed, the setup wizard and the USB installer take the join code from onemind fabric ticket (join_code, optional hub_addr), and a new onemind-fabric-join unit runs onemind fabric join so the owner approves the box on the hub. The old keys hub, join_token and nats_tls are refused; boxes set up before keep running and get a note that moving them onto the mesh means reinstalling. Image battery criteria F7 to F9 are pre-registered and implemented (mesh address and HTTPS with the box CA, Headscale refusing a made-up key, NATS refusals, one CA) and pass under KVM. A hub on a LAN without a router (an offline network, or the test VM's isolated one) takes its single LAN IPv4 address when there is no default route, instead of failing mesh setup.

Review fixes: joining from the image works with a read-only /etc (the hosts file is written in place when no temp file can be made next to it); onemind-nats waits for the mesh address only for the mesh leaf listener (marked by a comment line), so a box set up before the mesh still starts NATS after an update; and the Jetson layer ships hosts.default and no longer binds the mesh paths in its fstab (Jetson mesh is not part of this PR, not done).

Merged with the rescue console (CORE-UPDATE-9): the hub starts onemind-rescue on new and pre-mesh boxes, and its certificate is signed by the box CA where it now lives. On a mesh box it names only <box>.local and onemind.local, because the box CA's name constraints void any other name; a box set up before the mesh keeps the old names and its identity/ CA.
