Device capability card contract, part 1 (Refs #727): a JSON Schema and a JSON-LD context in sdk/schema for a card that says what a device can do, built on the W3C WoT Thing Description 1.1, with an om:safety block on every property and action (safety class observe, reversible, irreversible or physical; limits with units; needsHold, dryRun, sim, rate, safeState, askers, approvers, requires). The schema carries the class-to-risk table (observe read, reversible write, irreversible destructive, physical actuate plus the physical flag). A Python validator in sdk/tools/applib/devicecard.py refuses any credential field or user:pass URL, any number without a unit, a physical action without limits, a safe state, a hold or an owner as the only approver, and any agent as approver; problems name the rule and path, never a value. Two example cards (a temperature sensor and a relay) and one failing fixture per rule. The Go validator and the `onemind plugin card validate` command follow in part 2.
