The gateway can now scan images on the box itself. A hardened one-shot Kubernetes Job runs a Trivy pinned by digest against a vulnerability database also pinned by digest, offline after the first sync, and writes a scan record in the same shape as apps/*/scan.json. Community sources and migrated apps use it, so the existing rule "install needs a passing scan under 7 days old" can now be met on the box. A fixable CRITICAL vulnerability or a secret fails the scan, and any error counts as unavailable, never pass.

Fix round: the first database sync is now marked done only after it succeeds, so one network failure no longer locks the scanner into "unavailable" until a gateway restart; the next scan retries. The opt-in real-cluster test (ONEMIND_SCAN_IT=1) was run against a throwaway k3s v1.31 with the pinned Trivy, vulnerability database and Java database digests: a known-vulnerable old Alpine image scans as fail and a distroless image as pass. That run found that the Java database needed more than the 1Gi scratch space and 2Gi volume, so both are now 4Gi. The hardened install (deploy/install.sh) now also creates the fixed onemind-scan namespace and a narrow Role for it, and the gateway fence names that one namespace and only Jobs, NetworkPolicies and volume claims in it, so community-source and migrate scans work there too. The fence was also tested for real: with deploy/k8s/gateway-rbac.yaml applied to that k3s, the gateway identity could create Jobs in onemind-scan and run the whole scan test, but was refused a Namespace named anything else, a ConfigMap in onemind-scan, a Job in kube-system, and a onemind-scan Namespace without a restricted pod security level.
