Every filing path (app actions, handler types, feature types; never the secrets path) now asks one ordered decision before a request is stored and again before a standing approval may accept it: the stop buttons, Locked, deny rules, the token's scope and an unknown risk refuse at once (403 with the reason, audited); the hard floor (physical, destructive and actuate, tainted or exposed agents, anything that grants access, secrets, radio transmit, SMB shares for AI, a licence that is not green) always waits for a person; an untrusted clock or the floor's own settings switched off turn every rule off. New deny rules give a per-principal never for one type or a tier, checked before any rule: GET, POST and DELETE /v1/approval-denies and onemind permissions deny list, add and remove; adding one only tightens (the owner or the person who owns that agent), removing one is owner only with the passkey step-up. The clock guard keeps a high-water mark and, when ONEMIND_CLOCK_SYNC_FILE is set, needs the time-sync flag. An automation's request while automation is paused is now refused instead of filed, and a request with no known risk class is refused. New tables permissions_denies and permissions_clock. Gateway permissions design PR 8, D-027, D-028.
