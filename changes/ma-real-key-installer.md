The security build now makes the USB installer stick from the release-signed image (Refs #234, D-010, D-031). When its bundles were signed with the release keys, a new installer job copies only the public CA certificate the bundle was checked against (scripts/release/installer-payload.py). It assembles the x86_64-efi disk image with that certificate as the RAUC keyring and no signing key (make release-image, os/assemble/release-image.sh). It then reads the keyring back from the assembled image and refuses the image if it is not that CA. scripts/release/check-release-image.sh checks that RAUC accepts this run's bundle with the image's keyring and that the image has the same packages as the scanned and signed build. Then the job builds the stick and runs I1-I5. A box installed from it trusts the release CA, so every later release installs as an update: install once, update forever. Without keys (dry run, and image.yml always) the stick is built exactly as before with the throwaway dev CA, and every dry run also rehearses the release image with the dry run's public throwaway keyring under the same checks. The job reads no secret. The stick is a workflow artifact for now (named release or dev), not yet published.
