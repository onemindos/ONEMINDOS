Every joined machine now keeps a signed stop and revoke snapshot and enforces it on its own, also after a power cut or while cut off from the hub (D-029 "machines enforce a signed stop and revoke snapshot while offline", design step N7). The gateway signs one onemind.policy/v1 note per machine with the motion lockout, the agent kill switch, revoked job keys and, when set, the job kinds the machine may run, and raises its epoch on every change; jobs are now signed under the current epoch. The hub keeps the newest note per machine; each machine may read only its own, reads it before every job pull (and takes no job while it cannot), keeps the newest verified note on disk and never goes back to an older one. A job signed before the newest note is refused (stale_epoch), so a job queued before "Stop" can never run after it; while a stop is on, any job that moves or switches something is refused; a revoked key or a kind not allowed is refused. The note can only ever add a "no". GET /v1/fabric/policy and `onemind fabric policy` show it. A new pre-registered integration check (test/qemu/CRITERIA-NATS.md, NA1 to NA5) runs the whole NATS series in one hub: jobs reach a machine that was cut off and run once, local sign-in holds, the stop snapshot wins over queued jobs on reconnect, and with the gateway down machines keep working while unknown clients are refused.
