Every joined machine now keeps a signed stop and revoke snapshot and enforces it on its own, also after a power cut or while cut off from the hub (D-029 "machines enforce a signed stop and revoke snapshot while offline", design step N7). The gateway signs one onemind.policy/v1 note per machine with the motion lockout, the agent kill switch, revoked job keys and, when set, the job kinds the machine may run, and raises its epoch on every change; jobs are now signed under the current epoch. The hub keeps the newest note per machine; each machine may read only its own, reads it before every job pull (and takes no job while it cannot), keeps the newest verified note on disk and never goes back to an older one. A job signed before the newest note is refused (stale_epoch); while a stop is on, any job that moves or switches something is refused; a revoked key or a kind not allowed is refused. The note can only ever add a "no". So that a job queued before "Stop" cannot actuate after it: pressing the motion lockout or the agent kill switch puts the new notes on the hub before the call returns and, while a stop is on, purges every queued job that actuates something from the job queue; a machine reads its note again right before such a job, and refuses it while it holds no verified note at all (none yet, or the one on disk does not verify, which it logs loudly). If the hub cannot be reached, the stop still holds in the gateway, the failure is an audit line and a warning event, and the gateway keeps retrying. A corrupt epoch file is now an error that stops job signing loudly instead of a silent reset to epoch 1, and reading the policy no longer writes that file. Known and deferred to step 5 (the per-box fabric root key and its ceremony): the note is signed with the gateway's job key, so whoever holds that key can lift a stop. GET /v1/fabric/policy and `onemind fabric policy` show it. A new pre-registered integration check (test/qemu/CRITERIA-NATS.md, NA1 to NA7) runs the whole NATS series in one hub: jobs reach a machine that was cut off and run once, local sign-in holds, the stop snapshot wins over queued jobs on reconnect, nothing actuates without a verified note, a stop purges queued actuating jobs on every machine, and with the gateway down machines keep working while unknown clients are refused.
