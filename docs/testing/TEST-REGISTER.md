> **Explain it like I am the founder**
> Every row below is something we built (or are about to merge) that has **not** been proven where it matters: on real hardware, in real CI, with real accounts, or against an attacker. "Passed in a VM" or "passed in a container" is not the same as "passed on the Beelink", so those rows stay here until the real run passes.
> The **Who** column says who can run it: an agent in CI, an agent in a VM, you with the hardware, or you with an account (Apple, DigitalOcean, S3...). The **Now?** column says whether it can run today (`now`), only after a branch merges (`after <branch>`), or only once you act (`founder`).
> When you run one, add a line to [RESULTS.md](RESULTS.md) (or open a "Test result" issue) and change the row's **Status**. A failure becomes a fix PR; its number goes in the last column.

## How to read the table

- **Why** codes: `no-hw` (no hardware yet), `never-ci` (never ran in CI), `accounts` (needs an account or a paid service), `keys` (needs signing keys), `emulation` (passed only in QEMU, Lima, a container or a simulator), `not-merged` (lives on a branch).
- **Who**: `agent·CI`, `agent·VM` (a Lima VM or a CI runner with KVM), `founder·HW`, `founder·accounts`.
- **Status**: `not run`, `passed`, `failed`, `fix needed`. Only a run recorded in [RESULTS.md](RESULTS.md) can move a row to `passed`.
- **Decision**: the founder decision in [`docs/leap/DECISIONS-NEEDED.md`](../leap/DECISIONS-NEEDED.md) (F-xx) that blocks the test, if any.
- Board names are those in [`os/boards/`](../../os/boards/): `x86_64-efi`, `arm64-efi`, `vm`, `vm-do`. **There is no Pi 5 or Jetson image yet**; their rows test what exists (the kits, `install.sh`, `onemindd`).
