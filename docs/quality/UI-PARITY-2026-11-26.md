# UI and backend parity report

**Date:** 2026-11-26 · **Scope:** `release/next` at `04c039127`, plus the open PRs named below. **Requested by:** the founder, as one of the last tasks before the hardware install ("backend and front end 1:1"). **Tracking issue:** #1232 (Refs #234).

Read-only audit: nothing was built here. Where a table says "no caller", no screen, command or app was found calling that route.

**Method caveat, and the second pass.** The first pass searched the non-test source for route path strings. That cannot see SDK method calls: about 40 dashboard files build `new OneMind(...)` and call `sdk.x.y()` or `client.domains.list()`, and the path then lives only in `sdk/ts/src/client.ts` (and the Go SDK in `sdk/go`). That miss produced one wrong row (notification preferences). A second pass was done on 2026-11-26: every operation the hand-written SDKs wrap (TypeScript `client.ts`: instance, kiosk, domains, status, nodes, network, tips, apps list, actions, me.home, notifications devices, createChannel and preferences, audit; Go and Python wrappers) was mapped to its SDK method name, and each method name was searched in `dashboard/`, `mobile/` and the CLI, together with a path search that also covers `sdk.call({ path })` and the dashboard `read(client, path)` helper. Every must-have and should-have row was re-checked this way. What changed: the notification preferences row and S3 (preferences are in the dashboard), the push registrations row (the dashboard lists them), the windows wording, and the section 2 caveat. All other "no caller" rows held. The per-tag counts in section 2 come from the path search only and under-count operations reached through SDK methods; treat them as a floor.

## 5. Proposed ratchet

Add one test that reads `sdk/openapi/onemind-v1.json` and requires every operation id to declare its surfaces: dashboard, cli, mobile, or `none` with a written reason. Use the same ratchet pattern as `AWAITING_TOOL`: the list of undeclared operations starts as today's gaps and may only shrink. This turns BUILDER-BRIEFING item 6 from a review rule into a failing test.
