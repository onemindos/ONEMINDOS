# OneMind client SDKs (TypeScript, Python, Go), generated from OpenAPI

**Status:** proposal for the leap plan, 2026-11-12. Nothing here is built yet. **Epic ids:** DEV-SDK-1 … DEV-SDK-10.
**Serves:** contract `sdk/contracts/poc-v0.md` §3 (gateway REST, "OpenAPI published at `/openapi.json`") and §11 (agent principals, `/mcp`, catalog fields); brief 30 BD-02 (Go for CLI and `onemindd`, Python Core, TypeScript for SDK and UI) and D-B9.8 (OpenAPI published, contract tests); research 29 §7 (SDK, CLI, developer experience); D-001 (Apache-2.0 open core).
**Related specs (leap set):** the API spec owns the routes and the event stream; the plugin SDK spec owns manifests, `onemind plugin …` and widgets; the MCP spec owns `/mcp`. This file owns only the **client libraries** that call the gateway.

> **Explain it like I am the founder**
> Today three programs talk to your hub (the dashboard, the phone app and the `onemind` CLI), and each has its own hand-written copy of "how to call the hub". The phone app's copy was literally pasted from the dashboard's.
> This spec replaces those copies with one library per language, generated by a tool from the hub's own published description of its API, so they cannot drift.
> Developers get the same thing: `npm install @onemind/sdk`, `pip install onemind-sdk` or `go get …/sdk/go`, and they can list nodes, request an action and watch it get approved in ten lines.
> The libraries cannot approve anything an agent requests. Only an owner's credential can, and the hub checks that, not the library.

---

## 1. Goals and non-goals

| Goals | Non-goals |
|---|---|
| One source of truth: the gateway's OpenAPI document. Types in all three SDKs are generated from it; a CI job fails when they are stale. | Designing new gateway routes. Routes and the event stream belong to the API spec and a contract PR; this spec states what the SDKs need from them. |
| Three SDKs with the **same surface and the same behaviour**: auth, retries, idempotency keys, typed errors, event streaming, timeouts. | A plugin SDK (manifest, scaffolder, widget runtime). Separate spec; it *uses* this client. |
| Replace the hand-written clients in `dashboard/src/api/client.ts`, the mobile copy, and `httpGet` in `cmd/onemind/main.go`. | An MCP client. Agents may use `/mcp` (contract §11.3) or this SDK; both hit the same gateway rules. |
| Small and auditable: generated types plus a thin hand-written transport. Few runtime dependencies (TS: none; Go: standard library only; Python: `httpx`, `pydantic`). | NATS clients. Bus access is not part of the public developer surface in v0. |
| Publish to npm, PyPI and the Go module proxy from CI with trusted publishing and provenance, once the founder picks the accounts. | Any client-side enforcement of who may approve. The gateway is the only authority; the SDK only reports its answer. |

## 3. Design

### 3.1 The pipeline

```
core/onemind_core (FastAPI)
   │  python -m onemind_core.openapi > sdk/openapi/onemind-v1.json      (DEV-SDK-1)
   ▼
sdk/openapi/onemind-v1.json   ← committed, reviewed in PRs, diffed for breaking changes
   │  make -C sdk gen                                                  (DEV-SDK-2)
   ├─► sdk/ts/src/gen/schema.ts        openapi-typescript  (types only)
   ├─► sdk/python/src/onemind_sdk/_gen/models.py   datamodel-code-generator (pydantic v2 models)
   └─► sdk/go/internal/gen/types.gen.go            oapi-codegen (types only)
            │
            ▼
   hand-written thin layer per language (transport, auth, retries, errors, events, helpers)
```

**Why "generate types, hand-write the transport":** generators are good at types and poor at the behaviour that matters here (idempotent retries, read-back after an ambiguous approve, SSE resume, never logging tokens). The hand-written layer is about 400–600 lines per language, the same in all three, and is tested by one shared conformance suite (§7). The generated part changes whenever the API does; the hand-written part changes rarely.

### 3.2 What the spec must contain first (DEV-SDK-1, gateway stream)

| Need | Change in `core/` | Why the SDK needs it |
|---|---|---|
| Typed responses | `response_model=` on every route (Instance, NodeRecord, CatalogApp, Action, list forms) | Otherwise every response is `unknown` / `Any` / `interface{}` |
| Stable operation ids | `operation_id="nodes.list"` style on every route, checked by a test | Method names in three SDKs come from them; FastAPI's defaults change when a function is renamed |
| Open enums | Action `type` and `state`, node `status`, `board` documented as string enums with `x-onemind-open-enum: true` | New states (e.g. a future `awaiting_step_up`) must not crash old SDKs (§5) |
| Idempotency documented | `idempotency_key` description + the 200 replay response with the Action schema | So generated docs and SDK docs say the same thing |
| Error statuses on every route | already done via `error_responses(...)`; add 429 when the contract adds a code | Typed errors |
| Spec export without a server | `core/onemind_core/openapi.py`: build the app with test settings and print `app.openapi()` with sorted keys | CI generates without starting the gateway |
| API version | `info.version` = the contract version (`0.11.0` for poc-v0 §11), separate from the package version | SDKs record which contract they were generated from |

### 3.3 Generator choice

Versions were read from the registries on 2026-11-12. The repo rule (versions.lock, "never latest") applies: pin a release **at least 14 days old** when DEV-SDK-2 lands, with its checksum in `os/versions.lock.yaml`.

| Language | Choice | Licence | Latest seen | Output | Runtime deps it adds |
|---|---|---|---|---|---|
| TypeScript | **openapi-typescript** | MIT | 7.13.0 (2026-02-11) | One `schema.ts` of `paths` / `components` types | none (dev dependency only) |
| Python | **datamodel-code-generator** | MIT | 0.94.0 (2026-11-12, too new: pin the previous release) | Pydantic v2 models | `pydantic` (MIT), already used by `core/` |
| Go | **oapi-codegen** v2, `generate: models: true` only | Apache-2.0 | v2.8.2 (2026-10-31, too new: pin v2.8.1 or earlier) | Structs + enum constants | none for types-only output (checked in CI) |
| All | **oasdiff** (breaking-change check) | Apache-2.0 | v1.37.0 | Diff report, exit code on breaking changes | CI only |

Hand-written transports use: TS `fetch` (browser, Node 20+, React Native), Python `httpx` (BSD-3-Clause), Go `net/http`.

**Rejected:**

| Option | Licence | Why not |
|---|---|---|
| OpenAPI Generator | Apache-2.0 | Needs a Java toolchain; large, template-shaped output in three styles; hard to keep the three SDKs behaving the same |
| openapi-fetch (as the TS runtime) | MIT | Good, but our transport needs retries, read-back and SSE anyway; one more dependency for little gain. Revisit if the hand-written layer grows past ~600 lines |
| openapi-python-client | MIT | Generates `attrs` classes and its own transport; we want pydantic models matching `core/` |
| Microsoft Kiota | MIT | Heavy runtime packages in every language |
| ogen (Go) | Apache-2.0 | Generates a full client and server; more than we need, and its own runtime |

### 3.4 Layout under `sdk/`

```
sdk/
├── openapi/
│   ├── onemind-v1.json          # committed export of the gateway spec (DEV-SDK-1)
│   └── events-v1.json           # JSON Schema for event payloads (DEV-SDK-7, from the API spec)
├── Makefile                     # gen, check-stale, test (all three)
├── conformance/                 # shared cases: request → expected wire bytes and SDK result (DEV-SDK-8)
│   ├── cases/*.json
│   └── mock-gateway/            # tiny scripted HTTP + SSE server used by all three test suites
├── ts/                          # npm: @onemind/sdk
│   ├── package.json  tsconfig.json  README.md
│   ├── src/gen/schema.ts        # GENERATED
│   ├── src/{client,transport,auth,errors,retry,events,actions}.ts
│   └── test/
├── python/                      # PyPI: onemind-sdk, import onemind_sdk
│   ├── pyproject.toml  README.md
│   ├── src/onemind_sdk/_gen/models.py   # GENERATED
│   ├── src/onemind_sdk/{client,aio,auth,errors,retry,events}.py
│   └── tests/
└── go/                          # module github.com/onemindos/onemindos/sdk/go, package onemind
    ├── go.mod  README.md
    ├── internal/gen/types.gen.go        # GENERATED
    ├── {client,auth,errors,retry,events,actions}.go
    └── *_test.go
```

- Generated files start with a `// Code generated … DO NOT EDIT.` header and the spec's sha256, and are excluded from lint.
- `sdk/go` is **its own Go module**, so a third party who imports it does not pull `nats-server` and the rest of the root module. The root `go.mod` uses it with `require github.com/onemindos/onemindos/sdk/go v0.0.0` plus `replace … => ./sdk/go` (allowed because the root module is built, never imported). Releases are tagged `sdk/go/vX.Y.Z`.
- `sdk/ts` is an npm workspace package. `dashboard/`, `mobile/` and `site/` depend on it with a `file:` / workspace link inside the repo and on the published version outside it.

### 3.5 One surface, three languages

Method names come from the `operationId` (`<resource>.<verb>`).

| operationId | Route | TypeScript | Python | Go |
|---|---|---|---|---|
| `meta.healthz` | `GET /healthz` | `om.healthz()` | `om.healthz()` | `c.Healthz(ctx)` |
| `instance.get` | `GET /v1/instance` | `om.instance.get()` | `om.instance.get()` | `c.Instance.Get(ctx)` |
| `nodes.list` | `GET /v1/nodes` | `om.nodes.list()` | `om.nodes.list()` | `c.Nodes.List(ctx)` |
| `nodes.get` | `GET /v1/nodes/{id}` | `om.nodes.get(id)` | `om.nodes.get(id)` | `c.Nodes.Get(ctx, id)` |
| `apps.list` | `GET /v1/apps` | `om.apps.list()` | `om.apps.list()` | `c.Apps.List(ctx)` |
| `actions.create` | `POST /v1/actions` | `om.actions.request(req)` | `om.actions.request(...)` | `c.Actions.Request(ctx, req)` |
| `actions.list` / `actions.get` | `GET /v1/actions[/{id}]` | `om.actions.list()` / `.get(id)` | same | `c.Actions.List(ctx)` / `.Get(ctx, id)` |
| `actions.approve` | `POST …/approve` | `om.actions.approve(id)` | `om.actions.approve(id)` | `c.Actions.Approve(ctx, id)` |
| `actions.deny` | `POST …/deny` | `om.actions.deny(id)` | `om.actions.deny(id)` | `c.Actions.Deny(ctx, id)` |
| (helper) | polls or streams | `om.actions.wait(id, opts)` | `om.actions.wait(id, ...)` | `c.Actions.Wait(ctx, id, opts)` |
| (events) | `GET /v1/events` (planned) | `om.events.subscribe(...)` | `om.events.subscribe(...)` | `c.Events.Subscribe(ctx, ...)` |

`request` is the SDK name for `actions.create` on purpose: it says what an agent or a plugin is allowed to do (ask), matching the MCP tool `request_action`.

Python ships a sync client (`onemind_sdk.Client`) and an async one (`onemind_sdk.aio.Client`) over the same `httpx` code.

### 3.6 Auth helpers

| Helper | Reads | Use |
|---|---|---|
| `fromEnv()` / `Client.from_env()` / `onemind.FromEnv()` | `ONEMIND_HUB` + `ONEMIND_TOKEN` (the CLI's names), else `ONEMIND_GATEWAY_URL` + `ONEMIND_AGENT_TOKEN` (the §11.2 Secret an agent app gets) | CLI, scripts, in-cluster agents |
| `staticToken(token)` | a string | Dashboard and mobile after sign-in |
| `TokenProvider` interface: `token(): Promise<string>`, `onUnauthenticated(): Promise<boolean>` | anything | Later identity work (E8: passkeys, an on-box IdP, short-lived session tokens). A provider can refresh once on 401; the SDK retries that request one time only |

Rules, all three SDKs:
- The token goes only in `Authorization: Bearer …`. Never in a URL or query string, including the event stream (which is why the TS SDK does not use the browser's `EventSource`, see §3.9).
- Tokens never appear in errors, logs, `toString`/`__repr__`/`String()` output or debug hooks. The client prints as `OneMind(hub=https://hub.example:8080, principal=?)`.
- `baseUrl` must be absolute `http(s)://` (the mobile `normalizeHubUrl` rule moves into the SDK). Plain `http://` to anything but `localhost` prints a one-time warning in Node, Python and Go until the gateway's HTTPS lands (plan E3).
- Optional `whoami` is **not** in v0 because the gateway has no such route; the API spec may add `GET /v1/principal` and the SDK then exposes `om.principal()`.

### 3.7 Retries, idempotency and timeouts

| Call | Retried automatically? | How |
|---|---|---|
| Every `GET` | Yes | On network errors and 502/503/504: up to 3 attempts, full-jitter backoff from 250 ms, cap 4 s; honour `Retry-After` |
| `POST /v1/actions` (`request`) | Yes, safely | The SDK creates **one** idempotency key (UUIDv4) per logical call unless the caller passes one, and reuses it on every retry. A replay returns 200 with the original action; the SDK returns it the same way as a 201 |
| `approve` / `deny` | **No blind retry** | After an ambiguous failure (sent, then network error or 5xx), the SDK reads the action back. If it is decided and `decided_by.id` is the caller, it returns the action; otherwise it throws `AmbiguousResultError` with the last seen state. A double approve can never happen silently, and a 409 from a retry is never reported as success |
| Any 4xx | No | Except one token refresh on 401 (§3.6) and, when the contract adds it, 429 with `Retry-After` |

- **Default timeout** 10 s per attempt (the mobile client's value), overridable per call; Go uses the `ctx` deadline.
- **Expiry:** `request` takes `expiresIn` (default 24 h, the MCP default) and sends `expires_at` computed from the **hub's clock** when known (the dashboard's `Date`-header offset moves into the SDK as `om.hubOffsetMs()`).
- **Idempotency key reuse with a different body** surfaces as `ConflictError` with `reason: "idempotency_key_reused"` (parsed from the message until the contract gives it a code).

### 3.8 Typed errors

One base type per language carrying `status`, `code` and `message`; the `code` is exactly the contract §3 value.

| HTTP | `code` | TypeScript | Python | Go (`errors.Is`) |
|---|---|---|---|---|
| 401 | `unauthenticated` | `UnauthenticatedError` | `Unauthenticated` | `onemind.ErrUnauthenticated` |
| 403 | `permission_denied` | `PermissionDeniedError` | `PermissionDenied` | `onemind.ErrPermissionDenied` |
| 404 | `not_found` | `NotFoundError` | `NotFound` | `onemind.ErrNotFound` |
| 409 | `stale_precondition` | `StalePreconditionError` | `StalePrecondition` | `onemind.ErrStalePrecondition` |
| 409 | `expired` | `ExpiredError` | `Expired` | `onemind.ErrExpired` |
| 409/422 | `conflict` | `ConflictError` | `Conflict` | `onemind.ErrConflict` |
| any | `outcome_unknown` | `OutcomeUnknownError` | `OutcomeUnknown` | `onemind.ErrOutcomeUnknown` |
| 0 | `network` | `NetworkError` (incl. timeout, `timedOut: true`) | `NetworkError` | `onemind.ErrNetwork` |
| 2xx/other | `unexpected_response` | `UnexpectedResponseError` (HTML from a proxy, wrong JSON shape) | `UnexpectedResponse` | `onemind.ErrUnexpectedResponse` |
| — | ambiguous approve/deny | `AmbiguousResultError` | `AmbiguousResult` | `onemind.ErrAmbiguousResult` |

- A code the SDK does not know (added by a newer gateway) becomes the base `OneMindError` with that `code` string, never a crash.
- Go: `*onemind.Error{Status int; Code, Message string}` implements `Is` against the sentinels, so `errors.Is(err, onemind.ErrExpired)` works; `errors.As` gets the details. The CLI keeps printing `HTTP 401 unauthenticated: …`.
- The error message is the gateway's text. It is shown to people but **never parsed** for decisions except the documented idempotency case.

### 3.9 Event streaming (SSE)

The dashboard and phone poll today. The SDKs are built for a stream the API spec is to define; until a contract PR adds it, `subscribe` falls back to polling (every 2 s for actions, 10 s for nodes, matching the heartbeat).

**The shape** is defined by [API.md](API.md) §10 (DEV-API-8); the example follows it. A contract PR still has to add the route.

```http
GET /v1/events?types=action.*,node.status HTTP/1.1
Authorization: Bearer <token>
Accept: text/event-stream
Last-Event-ID: 1041
```
```text
retry: 3000

id: 1042
event: action.state_changed
data: {"schema":"onemind.event/v1","id":"1042","type":"action.state_changed","ts":"2026-11-12T10:15:02Z","subject":{"action_id":"act_7f3c"},"data":{"from":"dispatched","to":"succeeded"}}

: keepalive

id: 1043
event: node.status
data: {"schema":"onemind.event/v1","id":"1043","type":"node.status","ts":"2026-11-12T10:15:10Z","subject":{"node_id":"3f9c2a1b7d4e"},"data":{"status":"stale"}}
```

- **Events carry ids and states only**, the same "minimal data" rule as D-005 push. The SDK fetches the full object over REST when the caller asks for it (`{hydrate: true}`), so the stream never becomes a second source of truth and leaks little if logged.
- **Resume:** the SDK sends `Last-Event-ID`. If the server can no longer replay from it, it sends `event: stream.reset` and the SDK emits a `reset` to the caller, who reloads lists.
- **Liveness:** a `: keepalive` comment every 15 s; 45 s of silence means the connection is dead. Reconnect uses full-jitter backoff 1 s → 30 s, and honours `retry:`.
- **Transport:** TS reads the `fetch` response body as a stream (works in browsers and Node and keeps the token in a header; `EventSource` cannot set headers). React Native's `fetch` has no streaming body, so `@onemind/sdk` exports a pluggable `EventTransport` and a ready `xhrEventTransport` for React Native (incremental `responseText` on `progress`). Python uses `httpx` streaming; Go uses a `bufio` reader on the response body.
- **Unknown event types** are delivered as `{type, data}` without validation, so old SDKs keep working when the hub adds events.

### 3.10 Examples

**TypeScript** (dashboard, mobile, site, third parties):

```ts
import { OneMind, ExpiredError, PermissionDeniedError } from '@onemind/sdk';

const om = new OneMind({ baseUrl: 'https://hub.example:8080', auth: OneMind.staticToken(token) });

for (const n of await om.nodes.list()) console.log(n.hostname, n.status);

// Ask; never approve as an agent.
const a = await om.actions.request({ type: 'app.install', params: { app_id: 'uptime-kuma' }, expiresIn: '24h' });
console.log(a.id, a.state);                 // act_7f3c awaiting_approval

const done = await om.actions.wait(a.id, { timeoutMs: 10 * 60_000 });  // SSE if available, else polls
console.log(done.state);                    // succeeded | failed | cancelled | expired | outcome_unknown

// Owner screen (dashboard / phone):
try {
  await om.actions.approve(a.id);
} catch (e) {
  if (e instanceof ExpiredError) showToast('This request expired before you decided.');
  else if (e instanceof PermissionDeniedError) showToast('Only an owner can approve.');
  else throw e;
}

const stop = om.events.subscribe({ topics: ['actions'] }, (ev) => {
  if (ev.type === 'action.updated') refreshApprovals();
});
```

**Python** (agent apps such as Hermes, scripts, notebooks):

```python
from onemind_sdk import Client, errors

om = Client.from_env()   # ONEMIND_GATEWAY_URL + ONEMIND_AGENT_TOKEN inside an agent app
for n in om.nodes.list():
    print(n.hostname, n.status)

a = om.actions.request(type="app.install", app_id="ntfy", reason="owner asked for phone alerts")
print(a.id, a.state)                       # act_91d0 awaiting_approval

try:
    om.actions.approve(a.id)               # an agent token always gets this:
except errors.PermissionDenied as e:
    print(e.code, e.status)                # permission_denied 403

final = om.actions.wait(a.id, timeout=600)
print(final.state)
```

`reason` is sent only when the API spec adds it to `POST /v1/actions` (MCP's `request_action` already has it, §11.3); until then the Python and TS SDKs drop it with a debug log line, never with an error.

**Go** (`onemind` CLI, `onemindd`, third-party tools):

```go
import onemind "github.com/onemindos/onemindos/sdk/go"

c, err := onemind.FromEnv()           // ONEMIND_HUB + ONEMIND_TOKEN
if err != nil { return err }
nodes, err := c.Nodes.List(ctx)
if errors.Is(err, onemind.ErrUnauthenticated) {
    return fmt.Errorf("token rejected: set ONEMIND_TOKEN")
}
act, err := c.Actions.Request(ctx, onemind.ActionRequest{
    Type: onemind.ActionAppRemove, Params: onemind.ActionParams{AppID: "uptime-kuma"},
})
```

**CLI, after DEV-SDK-5** (the CLI becomes the Go SDK's first user; new commands belong to the CLI spec, shown here only as output of the SDK):

```text
$ onemind actions request app.install --app uptime-kuma
act_7f3c  app.install  uptime-kuma  awaiting_approval  expires 2026-11-13T10:15:00Z
Waiting for an owner to approve… (Ctrl-C stops waiting; the request stays open)

$ ONEMIND_TOKEN=$AGENT_TOKEN onemind actions approve act_7f3c

```

## 4. Security model

| Threat | Control |
|---|---|
| An agent or plugin approves its own request | The gateway refuses (403, audited; §3, §11.2). The SDK has an `approve` method because owners' apps need it; it adds no bypass and no "agent mode" that could hide the refusal. Conformance case `agent-approve-403` checks the SDK surfaces the 403 as `PermissionDeniedError` and never retries it |
| A retry turns one approval into two | Approve and deny are never blindly retried; read-back decides (§3.7) |
| A retried request creates two actions | One idempotency key per logical call, reused across retries; conformance case checks identical keys on the wire |
| Token leaks via logs, URLs or crash reports | Header-only tokens, redaction in every printable form, no query-string auth for SSE, a test that greps captured logs for the token |
| A proxy or captive portal returns HTML that is taken as data | Shape check on every 2xx (kept from the dashboard client) → `UnexpectedResponseError` |
| Plain HTTP on the LAN | Warning until gateway HTTPS (plan E3); then `https` becomes the default in docs and examples. Custom CA support: Node/Go/Python accept a CA bundle option for the per-box CA |
| Supply chain of the SDK itself | Pinned generators in `os/versions.lock.yaml`; generated code reviewed in PRs; zero runtime deps in TS and Go, two well-known ones in Python; publishing only from CI with OIDC trusted publishing and provenance (npm `--provenance`, PyPI attestations, Go checksum database); no long-lived registry tokens in the repo or in secrets |
| Event stream as a data leak | Events carry ids and states only (§3.9) |
| Prompt injection via `reason` or app text | The SDK passes strings through unchanged and labels them untrusted in types (`reason: UntrustedText`) so UIs render them as text, never HTML |

## 5. Versioning and compatibility

| Item | Rule |
|---|---|
| API path | `/v1` (contract §3). A breaking change needs `/v2`, served alongside `/v1` for at least two minor OneMind releases |
| Contract version | `info.version` in `onemind-v1.json` (e.g. `0.11.0`); every SDK exposes it as `SPEC_VERSION` |
| SDK versions | SemVer, `0.x` until the founder declares the API stable. All three SDKs share one version number and release together |
| Additive changes | New routes, fields, enum values and event types are minor releases. SDKs **ignore unknown fields** and treat enums as open (known constants + any string), so an old SDK keeps working against a newer hub |
| Breaking changes | Detected by `oasdiff breaking` against the last released spec; the PR needs the `api-breaking` label and a contract PR |
| Hub too old | The SDK reads `GET /v1/instance` `version` lazily; calling a route the hub lacks gives `NotFoundError` with a hint "hub version X does not support Y" |
| Deprecation | `deprecated: true` in OpenAPI → `@deprecated` in TS, `DeprecationWarning` in Python, `// Deprecated:` in Go; removed no sooner than the next major |
| Runtimes supported | Node 20.19+ (the dashboard's floor) and evergreen browsers; React Native via the app's Expo SDK; Python 3.11+ (to confirm against `core/pyproject.toml`); Go matching the root `go.mod` (1.26) |

## 7. CI staleness and quality checks (`.github/workflows/ci-sdk.yml`)

Runs on every PR that touches `core/onemind_core/**`, `sdk/**`, `dashboard/src/api/**`, `mobile/src/api/**` or `cmd/onemind/**`:

1. `python -m onemind_core.openapi > /tmp/spec.json`; **fail if it differs from `sdk/openapi/onemind-v1.json`** ("the gateway changed: run `make -C sdk gen` and commit").
2. `make -C sdk gen`; **fail if `git diff --exit-code sdk/` is not empty** ("generated SDK code is stale").
3. `oasdiff breaking` against the spec of the last `sdk-v*` tag; fail without the `api-breaking` label.
4. Test suites: `vitest` (sdk/ts), `pytest` (sdk/python), `go test ./...` (sdk/go), each running the shared `sdk/conformance` cases against the mock gateway.
5. Integration job: start the real gateway with the `noop` executor and SQLite, run the three SDKs' smoke scripts (list nodes, request, agent approve → 403, owner approve → succeeded).
6. Dependency guard: TS `dependencies` must be empty; `go list -m all` inside `sdk/go` must show no third-party module; Python runtime deps limited to `httpx` and `pydantic`.
7. Generator pins: the generator versions used must match `os/versions.lock.yaml` (the existing `test/unit/test_versions_lock.py` pattern).

Example failure the developer sees:

```text
sdk: generated code is stale
  M sdk/ts/src/gen/schema.ts
  M sdk/go/internal/gen/types.gen.go
Run: make -C sdk gen && git add sdk/
```

## 8. Test plan and acceptance criteria

| # | Test | Acceptance |
|---|---|---|
| T1 | Spec export | `onemind-v1.json` has an `operationId` and a typed 2xx schema on all 10 routes; a test fails if any route lacks them |
| T2 | Staleness | Adding a field to `Action` in `core/` without regenerating fails CI step 1 or 2 with the message above |
| T3 | Conformance (≥ 25 cases, all three SDKs) | Identical results in TS, Python and Go for: each error code → its typed error; HTML 200 → unexpected response; unknown error code → base error; unknown enum value accepted |
| T4 | Idempotency | Mock drops the first response of `POST /v1/actions`; the retry carries the **same** key; exactly one action exists |
| T5 | Ambiguous approve | Mock applies the approve then drops the connection; SDK returns the action after read-back. If the mock shows `decided_by` = another owner, SDK throws `AmbiguousResultError`. No case sends approve twice |
| T6 | Agent cannot approve | Against the real gateway: agent token approve → `PermissionDeniedError`, status 403, one `authz.denied` audit line, no retry on the wire |
| T7 | Token hygiene | Run every case with a recognisable token; captured logs, error strings and printed clients contain zero copies |
| T8 | SSE | Resume with `Last-Event-ID` after a forced disconnect loses 0 events; 45 s without a ping triggers reconnect; `reset` is surfaced; React Native transport passes the same cases in the mobile test runner |
| T9 | Polling fallback | Against a hub with no `/v1/events` (404), `subscribe` and `wait` still deliver the state change within 2 × the poll interval |
| T10 | Consumers | Dashboard and mobile test suites pass on the SDK with their copied clients deleted; `go test ./cmd/onemind/` passes on the Go SDK with `httpGet` deleted |
| T11 | Size | `@onemind/sdk` minified + gzipped ≤ 15 kB without the generated types (types are erased at build) |
| T12 | Publishing dry run | `npm pack`, `python -m build` and a Go tag on a fork install cleanly in fresh containers (Node 20, Python 3.11, Go 1.26) and run the smoke script |
| T13 | DX target | From `npm install @onemind/sdk` to listing nodes from a script in under 5 minutes using only the README (timed once, recorded in the PR) |
