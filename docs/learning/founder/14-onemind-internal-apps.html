How they differ

Three kinds of app run on a box

Every app, whoever made it, goes through the same gateway: the same sign-in, the same approvals, the same audit log. What changes is who vouches for it and whether it can leave.

How AI reaches them

An agent can read and ask; only a person can say yes

Agents such as Hermes connect to one door, the gateway's MCP endpoint at /mcp. They never get an app's own login and never talk to NATS directly.

Agent

Hermes, Claude, any MCP client, with its own scoped token

Gateway /mcp

The only place permissions are checked

Tools

Read tools answer now. request_… tools only file a request

Approvals

The request waits with its exact plan and an expiry

A person

Approves with a passkey; holds 2 s for anything physical

Built-insEach descriptor lists its actions; those marked mcp: true become request_<action> tools. A switched-off built-in disappears from the tool list and its routes answer 409.
Market and custom appsAn app declares tools in spec.extensions.tools as read, write or actuate. The gateway calls the app with a short-lived signed credential (E6). actuate is refused today.
Built-ins speak tooEach built-in has an app identity (app:<id>) so it can post to the one inbox. It can never request or approve anything.
No path to "approve"A static test proves nothing reachable from /mcp can call approve or deny.

What to build next

Register what already works as built-ins

Work, Automation, Machines and Agents run today but sit outside the signed list, so they cannot be switched off, are missing from Market's Built in area and give agents no standard request tools. Small, mechanical, high value.

The Map screen (#653)

The centre of the Atlas design. The live asset stream it needs (#606) and offline map packs (#652) are already merged; nobody has started the screen. The phone Map tab (#656) follows it.

Notes, then Documents (#650)

Daily-use apps that keep their only copy in Files, which already exists. They make the box a place people return to every day.

Video and cameras (#662, #663)

Cameras feed the Map, security and the greenhouse and site-operations paths.

Small everyday apps (#885 to #890)

Scanner, Recorder, Weather, Find My Devices, Habits, Translate. Well scoped for Codex once the app SDK templates land.

Waiting on you

  • Which built-ins are always on. The design proposes Files, Approvals, Settings and Market can never be switched off. Confirm or change the list.
  • Signing for custom apps. Does an app you build yourself need a signature, or is your owner approval enough?
  • Which builder takes the Map screen (#653). Codex after the phone work, or the Claude builder now.
